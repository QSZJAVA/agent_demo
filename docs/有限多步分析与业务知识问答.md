# 有限多步分析与业务知识问答

“分析与问答”在明确选择的一家公司和一张授权报表内，组合查询、统计、排名、明细展开、对比和知识检索。它复用查询工作区的完整快照，展示每一步的中间结果和回答依据。

当前链路为 `real,mcp`、`agent.semantic.mode=active`、`deepseek-v4.1-flash`、原生 JSON Schema、thinking 关闭，业务记录通过认证 HTTP MCP 读取。该入口只进行读取和分析。真实工单、外部 ERP、正式企业身份和生产准入仍待相应环境接入或验收。

## 开始一次分析

1. 打开左侧“分析与问答”，明确选择公司和报表。
2. 输入完整问题，例如：“按产品汇总 2026 年 9 月销售金额，取金额最高的两个产品，展开它们的相关单据，再说明销售金额的口径。”只能使用当前目录存在的字段；缺少“客户”等字段时，系统会要求明确可支持的口径。
3. 查看计划目标和各步骤状态。金额、计数、均值和排名由程序基于完整快照计算，模型负责规划与说明，并接受独立复核。
4. 行结果先展示至多 20 条，“查看完整明细”在原快照上分页；分组统计先展示至多 30 组，排名仍使用完整分组集合。
5. 展开回答中的“依据”，核对实际来源、版本、适用范围、时间和原文。没有充分依据的问题会明确说明，冲突资料不会被静默择一。

查询工作区中，单一公司、单一报表的报表快照提供“分析此结果”。选定的快照必须仍属于本人并且有效；从它展开的明细不会重新读取已经变化的来源。需要最新数据时明确选择“改用当前数据”。

每次提交的是独立完整问题。系统不从历史聊天自动继承未说明的条件，也不把“再来一次”解释为对某份历史结果的隐式引用；已有查询结果通过界面明确选择。

## 支持的有限步骤

| 操作 | 输入与结果 | 约束 |
| --- | --- | --- |
| 基础查询 | 授权报表的完整有界结果 | 固定当前公司、报表和 REPORT 数据域，保留 AND/OR、空值、排除与精确上下界 |
| 引用快照 | 用户选定的本人查询 | 不重新调用来源或模型完成翻页，失效快照拒绝 |
| 分组与趋势 | 零至三个维度、按日/月统计、完整期间对比 | 复用 P1 精确十进制和期间可比性判定，最多 500 个分组 |
| 排名 | 行字段，或分组的计数、金额合计、均值 | 明确数量为 1 至 50；并列稳定，金额排名要求唯一币种，候选不足明确失败 |
| 展开相关明细 | 同一行集合的分组排名 | 只展开原快照中满足所选维度、币种和期间的明细，保留大小写、尾随空格和空值差异 |
| 查询对比 | 两个完整基础查询 | 比较集合与精确金额差异，分别记录观测时间，不声称跨来源全局事务 |
| 知识检索 | 当前授权并生效的目录、词典、规则、制度片段 | 先授权和检查版本/生效期，再进行原问题、多种检索表述、结果融合和相关性重排；无命中和截断明确显示 |

比较来源由程序根据完整结果同时生成记录数及金额的有符号差额、绝对幅度和方向。例如差额为负时，可引用“之后集合比之前集合减少”的确定性描述；金额仍逐币种计算并保留十进制精度。这些描述只说明集合差异，不能推断业务增长或变化原因。只有实际来源提供的幅度才可引用，数字校验不会把任意负数自动当作正数依据。

一次任务至多 6 步、2 份基础查询或已有快照、10 次模型调用，整轮 240 秒，每次模型传输至多 40 秒。规划/复核及回答/依据复核各有最多两轮机会，共用总预算。知识改写和相关性重排按整份计划各批量调用一次，不随知识步骤数量增加调用次数；没有知识步骤时不进行这两次调用。实际模型请求体上限 128 KiB，回答依据上限 80 KiB，持久步骤上限 512 KiB。超限明确失败，不无标记截断为完整结论。

仅允许引用前面的兼容步骤，不能构造循环、SQL、自定义表达式、任意工具调用或任意网络抓取。不支持的跨源关联和业务写入会要求调整任务。规则解释并不证明特定单据可派单；需要单条资格事实时使用现有业务查询，实际派单继续核对原有待确认清单并明确确认。

## 业务知识维护

普通用户可在自己当前授权的范围内问答。管理员通过“业务知识资料”维护同一范围内的制度，仍须拥有对应公司和报表权限。

- 新资料先保存为草稿，填写标题、实际来源名称、正文、生效日期、可选失效日期和变更原因。来源链接可空；仅作为引用信息，不由服务器抓取，不能包含凭据、查询串或片段。
- 正文可手工录入或从本地 `.txt` / `.md` 导入。文件须为有效 UTF-8、最多 64 KiB，完整正文最多 12,000 个 UTF-16 字符；超过预算会拒绝，不导入部分文本。导入只填入编辑器，仍需核对实际来源、适用范围并保存草稿；不会自动发布，Markdown/HTML 内容按文本处理。
- “保存草稿”不替换现有发布版本。编辑列表同时显示编辑版本和发布版本；有差异时显示“有未发布修改”。
- “发布”须确认具体资料、版本和原因，发布指针转向不可变的新版本。并发版本冲突时刷新核对，不能自动覆盖。
- “停用”撤销现行发布依据，版本历史仍保留。历史页面展示最近 50 个版本的原文、状态与原因。
- 生效日期按上海时区计算，包含开始当天、不包含失效当天。未来或过期资料不进入回答。单一公司/报表范围至多保留 100 份资料。

本系统不提供虚构企业制度。未录入正式资料时，回答可以引用现有目录、字段、业务词典和当前有效派单规则；这些来源不能代替尚未提供的报销标准、组织制度或外部审批记录。测试中的合成制度仅用于验证功能和边界。

知识正文、目录说明和来源链接属于数据。即使其中出现要求忽略约束、切换身份或执行操作的文字，也不能授予权限或调用写接口。模型为每项说明选择本轮实际片段编号，程序从已保存来源回填原文，并检查编号与数值；独立真实模型再复核结论是否受所选片段支持。较长知识优先在段落、句子边界分块，并保留至多 160 字符的相邻上下文；长句仍可能需要切分，片段不等于完整制度。标题、版本、范围、时间与正文共同受 2000 字符引用上限保护，行号及字符位置指向同一份脱敏后的来源全文。分块算法版本进入知识指纹。该机制有明确验收范围，不代表任意自然语言下绝无错误。

回答的原生 Schema 把可选引用限定为本轮真实编号。每条说明独立核验其引用；跨步骤复述总量时，必须同时选择对应步骤的来源。金额按精确十进制核对，日期与时间按完整值独立核对：ISO 观测时间可以支持同一天的日期说明及已有精度，不能重组日期组件、换算时区，或把日期数字当作金额依据。同一句日历区间允许末端省略已明确的年月，例如“2026年9月1日至14日”按两个完整日期核验；省略信息不能跨字段、跨句或跨来源继承，也不自动跨月跨年。非法或倒序日期明确拒绝，日期端点不能支持记录数差值、金额或持续天数。引用不足的有界修正提供实际包含该数字或完整日期时间的候选编号，候选只帮助定位原文，不自动补引，也不证明业务含义相同。已完成行步骤的只读分页能力写入对应证据，并使用页面从 1 开始的编号；回答与复核共享这些依据，并明确区分基础全集、排名选集和展开选集的统计口径。

## 知识检索与试查

知识检索先限定当前权限、已发布版本和生效期间，再匹配实际资料标题与正文。系统生成的报表标识、生效日期、行号和片段编号只用于核对引用，不参与正文召回；例如适用范围中的 `rpt-sales-order` 不会让无关中文资料命中 `sales`。英文、数字及下划线标识按完整词界匹配，统一大小写、全半角与空白；`tax` 不会命中 `syntax` 或 `tax_id`。中文采用二字、三字片段召回，结果仍需按原文核对。

如果原问题完整命中同一公司/报表词典中的字段名或别名，检索会补充该字段已经配置的其他名称。例如管理员为 `amount` 配置了“销单值”，输入这个名称即可召回使用 `amount` 的制度。扩展不递归，不从业务定义正文、公司别名、单位或枚举中猜测同义关系，也不能凭检索扩展就认定“销售金额”和“已收款”等指标等价。每轮最多 256 个直接词项、64 个扩展词；扩展截断会明确显示。

分析中的知识步骤采用模型辅助的多查询 RAG：在已独立复核的知识子问题上，一次真实模型调用为每题补充至多两种检索表述。模型响应使用两个明确的可空字段限制数量，额外字段和非法内容仍被拒绝，不截取超额输出作为成功。用户原问题与子问题仍参与召回，不由改写替代；改写可以补充同义或跨语言表达，但只用于查找资料，不是新的业务条件、正式词典或回答事实。

每路在同一份完整授权语料内执行词项及配置别名检索，以片段 ID 去重计算匹配并集，再以有权重的排名融合、来源均衡和问题轮询分配候选。整轮最多 24 个不同片段，重排输入最多 48 KiB；按实际 UTF-8 字节测量，不截短原文。真实模型对各题候选做相关性重排，必须完整保留每个候选，服务器拒绝漏项、重复、未知或跨题编号。重排传输使用本次服务器短编号，核验后映射回原来源标识，避免长编号耗尽输出预算。

最终每题仍先返回不同来源，再补充同来源片段，最多 12 片。支持、反驳、适用条件和例外都属于相关资料，不能只选符合某个预想答案的来源；超过来源数或字节预算时无法承诺覆盖全部冲突。界面显示多路表述、实际召回路径、候选/已重排片段数以及搜索、命中、返回的不同来源与片段数。配置别名与模型改写分别展示，相关性次序不是答案置信度。回答与独立复核读取同一覆盖信息，截断的回答必须说明限制。

该实现使用现有真实对话模型增强检索，不使用嵌入向量。未来接入向量检索前，仍须验证独立嵌入端点、版本化索引、出站数据边界和专项语义质量，不能把当前结果称作向量数据库验收。方案及取舍见 [RAG 实施计划](RAG语义检索与分析恢复实施计划_2026-10-12.md)。

检索执行事实明确区分“本次未检索知识”和“已检索但没有命中”。来源数与片段数使用各自单位，不能把一份资料的多个片段当成多个独立来源，也不能把未执行写成没有制度。知识资料的公司/报表是授权隔离范围，报表名称和字段不能证明某类主题的资料不存在；明确范围内的知识问题先检索实际已发布资料，再判断依据是否充分。独立复核同时检查结论和限制说明，不因等价表述拒绝，也不因拒绝理由自相矛盾就跳过复核。

“知识检索范围说明”是程序根据实际结果生成的独立引用依据，记录来源数、片段数和截断情况。回答复述计数时须引用它并接受同一数值校验；该说明不属于制度正文，不占最多 12 个知识片段的预算，也不表示系统读取了业务明细。没有因预算省略候选或别名表达时，不能把预算作为依据不足的原因；无命中只表示本次未找到可引用依据，不能据此断言现行资料没有某项规定。

管理员在“业务知识资料”中使用“检索试查”：

1. 选择公司、报表，在“需要查证的问题”中输入术语或完整问题。用“词法试查（不调用模型）”核对精确词项与配置别名，或用“语义试查（真实模型）”检查实际 RAG 链路。
2. 查看来源覆盖、检索表述和资料原文，核对版本、生效范围及命中路径。语义试查另外展示已重排候选和上下文预算；没有候选时明确未执行重排。
3. 草稿不会用于检索；编辑草稿仍检索现行发布版。发布新版或停用后，旧试查结果会清除，重新试查使用最新有效依据。
4. 修改问题、切换范围、刷新或离开页面后，旧请求即使稍后返回也不能填入新页面。没有命中可进一步明确术语或检查资料发布、生效情况。

两类试查都不读取业务明细、不创建分析任务，也不保存试查问题。词法入口 `POST /api/analysis/knowledge/search` 不调用模型；语义入口 `POST /api/analysis/knowledge/search/semantic` 与分析共用完整 RAG，至多两次真实模型调用、80 秒，并与分析共享资源配额。二者只接收 `companyCode`、`reportId`、`question`，普通用户无维护权限时拒绝访问。每次真实调用前后及返回前重新核对身份、范围、版本与配置；失败不自动切回词法结果，也不显示旧结果冒充本次成功。语义试查的失败日志只记录匿名尝试号、阶段、耗时与真实用量，排除问题和来源正文。实际问答继续经过真实模型规划和独立复核。

## 状态恢复与失效

最近任务按租户和本人隔离，至多保留 50 项有效任务。提交请求号绑定完整输入，同一请求号重试只回放原任务；页面刷新和明细翻页不会再次消耗模型调用。正在执行的任务可以取消；取消会撤销原令牌，迟到结果不能覆盖终态。

首次发送前，页面先把完整问题、范围、明确快照与请求号保存到当前标签的会话存储，并回读核验。保存器用当前登录身份及会话的摘要隔离记录，不另存原始令牌。网络中断、服务暂不可用或响应无法确认时，表单锁定并显示“核对本次提交”；同一标签刷新、离开后返回仅恢复原载荷，不自动发送。显式点击核对后，继续使用原请求号查回同一任务，不能把未知提交当作终态重做。

服务器明确返回当前协议的拒绝结果后，才解除该次待核对记录；无法确认的响应继续保留。会话存储不可用时不发送新的首次提交；恢复入口会撤销旧加载、历史及明细请求，迟到结果不能覆盖新状态。记录最多保留 24 小时，换登录、损坏或过期时说明无法恢复并提示从最近任务核对；不迁移其他会话的记录，也不承诺跨标签或跨浏览器恢复。

终态任务可使用“补充问题”或“按此问题重新分析”，将原问题和范围填入表单；这一步不执行模型。原任务明确引用了快照时，先重新核对快照及范围；失效时需要显式选择其他数据或“改用当前数据”。补充或核对后点击“开始分析”才以新请求号创建新任务，原任务保留。提交传输结果未知时的重试继续沿用原请求号，二者不是同一种重试。

每个实例最多两个分析工作线程，准入限制为同用户两个活动任务、同租户八个活动任务，并复用调用速率和并发配额保护。模型与 HTTP 读取在事务外执行。排队超过 120 秒或执行失租明确中断，不自动重放模型；重新分析需要用户显式提交新的请求。

执行配置冻结模型、提示、Schema、检索算法及预算。Schema 摘要递归规范对象键序，避免不同 JVM 的集合遍历顺序把未变的契约误判为版本变化；实际字段、类型、数量约束及保留的数组次序变化仍会产生不同摘要。

任务及证据最多保留 24 小时。当前权限、公司/报表口径、有效规则、知识发布版本、生效日期或基础快照变化时，读取会重新校验并拒绝失效结果。草稿编辑不改变已发布依据。快照删除、过期或中间明细缺行也会使相关分析不可用；它们不能从历史展示负载重建授权事实。

部分计算步骤失败时，已成功步骤与失败原因分别保留，不把整轮称为成功。修正反馈包含被拒绝草稿和具体问题；复核响应自身格式错误只重试复核，语义复核拒绝才重新生成计划或回答，全部调用仍受原总预算限制。真实模型不可用或输出不可靠时显示失败/澄清；原生用量缺失保持未知，不能用零或估算费用冒充实际计量。模型已返回但后置权限或版本校验拒绝发布时，保留已经发生的真实用量并记录拒绝状态。

模型传输入口对原始 HTTP 响应另设 512 KiB 硬预算；正文回答仍受 128 KiB 上限约束。成功响应须满足当前 JSON 协议、有效完成选项与安全元数据，空响应或畸形响应在进入 SDK 前拒绝，避免 SDK 把完整提示写入诊断。失败日志只包含状态、固定错误分类、字节数、选项及摘要，诊断最多保留 16 KiB 前缀供内存分类，不输出原始正文、任意错误消息或凭据。原因链最多检查 8 层，按异常类型区分取消、中断、超时、DNS 或 TLS 等类别，未知类名仅保留摘要，不凭自由消息猜测根因。媒体类型错误与正文是否可解析分别说明；HTTP 400、网关失败与模型语义拒绝分别保留证据，不增加隐式重试。

## 验证与运行准备

P2 实施和验收范围见 [实施计划](P2有限多步分析与知识问答实施计划_2026-10-11.md)与[完成报告](review/P2有限多步分析与知识问答实现与验收_2026-10-12.md)；后续检索优化见[检索准确性与试查计划](知识检索准确性与试查实施计划_2026-10-12.md)和[本轮验收](review/知识检索准确性与试查实现与验收_2026-10-12.md)。最新空库基线为 47 张业务表、557 个字段。旧本机演示库进入该基线须另行获得针对 `report_demo` 重建的数据操作授权，不自动修复 Flyway 校验和。

取得本轮专用隔离数据库授权后，真实链路专项入口为：

```powershell
./tools/test-analysis-knowledge.ps1 -AllowIsolatedDatabases -Live
```

浏览器联合验收在此基础上增加 `-Browser`，夹具等待实际界面验收明确通过的完成信号；中止或仅停止进程不能计为通过。它会建立并记录 `analysis_knowledge_it_<UUID>`，只清理本次创建的目标，保留执行前已有数据库。单独的程序回归、数据库状态机断言、真实模型/HTTP MCP 与浏览器检查须分别记录，不能相互替代。

检索试查的浏览器夹具使用 `-SearchBrowser`，提供已发布字段别名和明确标记的合成资料；以新的 `-EvidenceName` 保存本轮结果，避免覆盖历史验收。保留此前 P2 归档的版本与实际证据范围，不将新检索能力写成已经在旧版本执行过。

新增 RAG、文本导入和历史重做的浏览器夹具使用 `-RagBrowser`；同样必须保存实际界面检查并明确验收完成。验收后保留 Codex 内嵌浏览器标签，避免已知的关闭/销毁崩溃触发点。

专项检索金标在 `tools/fixtures/knowledge-rag-regression-v1.json`，由 8 份合成资料和 5 个独立标注问题构成，尚未经业务方审阅，不代表真实企业知识盲评。真实回放生成 `rag-observations.json` 后，可用 `tools/knowledge-rag-evaluation.cjs` 复算相关来源召回率、首个相关来源次序、反对依据保留、无命中及模型用量；缺失案例、未知用量或未完成回答复核不计为通过。离线评分器测试已纳入 `test-regression.ps1`，其结果与真实模型质量分开报告。
