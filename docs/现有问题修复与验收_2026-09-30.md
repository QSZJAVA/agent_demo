## 操作和权限边界

- 管理员必须仍处于启用状态，且有权访问原预览中全部公司/报表。业务侧重新从数据库解析实际管理员，不接受调用者伪造 admin 标记。
- MCP `dispatch_lookup` 可选 `requestOperatorId` 指定原操作者；身份字段 `operatorId` 始终代表实际管理员。不传该参数保持原本的本人查询行为。
- 代核对绑定已有同租户清单和稳定请求号；UNKNOWN 保留待核对状态，不自动重发。未保存外部请求号的 PENDING 条目可按确定的 `planId-itemId` 核对未发送结果。
- 核对审计记录实际管理员；清单及结果卡片继续属于原操作者。管理员核对不恢复原账号、不修改账号权限、不调用 submit。
- 重试失败仍要求原操作者有效且保有当前公司/报表权限，随后继续执行原有版本、状态与事务复核。

## 部署配置

同源部署无需设置 CORS；分域使用 `CORS_ALLOWED_ORIGINS=https://实际前端域名`。反代启用登录时，必须配置 Agent 的 `TRUSTED_PROXY_CIDRS`，否则安全默认仍忽略转发头。

```text
# 同机代理示例；仅当这些地址确实是代理连接来源时使用
TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
```

容器代理使用实际 IP 或专用网段。不得设置为全部公网地址。代理需追加或重写 X-Forwarded-For；应用从最靠近自身的可信代理向前解析，遇到第一个不可信地址即停止，忽略其左侧可能伪造的值。配置已接入 application.yml、.env.example 和现有 Compose 的环境变量传递。新配置默认不扩大信任范围。

客户端应将三张报表分页返回的 `id` 当字符串，并以字符串列表调用手工派单接口。数据库仍使用 Long/BIGINT，本次只改变 API 表示。
