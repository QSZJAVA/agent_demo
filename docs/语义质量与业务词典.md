# 语义质量与业务词典

当前 P0 为真实模型助手增加阶段诊断、按业务范围发布的词典、查询条件解释与编辑，以及可核验的澄清按钮。使用现有 `real,mcp`、`agent.semantic.mode=active`、真实模型接口与认证 HTTP MCP；模型配置继续由现有启动配置提供，原生 JSON Schema 与 thinking 配置以实际运行记录为准。

页面入口是导航中的“语义质量”。当前实现、失败与最终验收范围以 [P0 验收记录](review/P0语义质量与交互验收_2026-10-11.md)为准；这些功能不表示已经完成正式外部认证、ERP、生产容量或灾备验收。

## 诊断与反馈

“诊断记录”仅列出本人、且当前仍有权读取的会话。记录按可靠会话事件游标分页，每页最多 20 条。撤权、删除请求或会话关闭后，历史诊断和反馈入口同样拒绝访问；管理员不能借这个入口读取他人的诊断。

“详情与反馈”显示目标判断、任务规划、独立复核各次实际调用的耗时、模型名称、校验和修正记录。诊断保存模型契约及 Schema 摘要、词典指纹、共同参考时刻和字节数，不保存原始模型提示或响应。用户原文按现有统一规则脱敏。

“计划通过”只表示规划检查通过，业务事实和执行结果仍须查看对应查询卡片或派单任务。缺少端点原生 `usage`、某一计量字段缺失或数值非法时，用量保持未知；SDK 默认零不当作真实零。实际零计量可保留为零。当前普通助手费用没有可信价格配置，明确显示未知。调查模块采用同一原生计量判断，并继续受原有价格与缓存计量完整性约束。

用户可以区分“系统理解有误”与“正常调整查询”。反馈关联确切诊断，网络重试沿用同一请求号；同号不同内容或不同目标返回冲突，不覆盖先前记录。反馈按目标独立分页，始终标记“待审核”，不会自动修改词典、提示或变成训练标签。

## 词典维护

在“业务词典”选择数据域、公司和报表，再编辑当前范围的完整定义。普通用户只能读取授权范围；发布需要管理员身份和当前公司、报表权限，同时复查读取时版本。切换范围或修改确认中的表单会使原发布操作失效。

| 定义 | 含义与限制 |
| --- | --- |
| 公司名称、别名 | 解释该公司在当前范围的称谓；相同别名不合并两个公司身份 |
| 字段别名、业务定义 | 只能补充当前目录已有字段，不能创造可查询列或扩大权限 |
| 来源单位、币种 | 来源单位明确后才可增加换算；未核实币种留空，不能跨未知币种合计 |
| 单位倍率 | 字符串精确十进制，正值；与来源数值共用精度和指数上界，不做浮点换算 |
| 枚举与别名 | 按来源类型校验；同一别名不能指向不同值，数值等价枚举不重复发布；文本编号保留前导零 |
| 时区、财年起始月 | 本轮三个模型阶段使用同一参考时刻及范围日历 |
| 已维护非工作日 | 明确列出的日期事实；当前未接入完整企业工作日历，不能据此宣称准确计算全部工作日 |

先填写发布原因，再使用“检查草稿”检查字段、类型、冲突和版本。检查不发布、不调用模型。点击“发布本范围词典”并确认后，服务端保存定义与版本历史，递增相关报表目录版本，使旧预览和清单继续受到版本保护。模型调用期间词典或权限变化时拒绝发布旧结果，用户应按最新范围重新发起请求。

词典复用 `operations_policy` 与 `operations_policy_revision`，由专用键及业务权限入口管理；普通运营策略接口不能读取或写入这些键。当前不增加业务表或历史数据兼容协议。单范围历史最多显示最近 50 个版本。全部授权词典超过范围或输入体积预算时整体拒绝，不截断后冒称完整上下文。

## 条件解释、编辑和澄清

最新成功查询卡片显示完整条件及来源，区分本轮新增、保留和删除，另标明公司/报表范围及 AND/OR 组合是否变化。来源只展示通过独立复核的证据；缺少证据时明确不可用。

独立复核在冻结期望前同时核对原子条件与组合。程序对同一作用域内至多 12 个具备唯一、不重叠本轮证据的条件，检查证据之间明确的 AND/OR 和括号关系；冲突让真实模型在原有预算内修正自身复核，不生成或自动修改计划。值内连接词不参与分组；重叠或重复引用、继承条件、整体否定、没有括号限定的混合优先级和超预算表达仍由独立模型理解。这个有界检查不代表覆盖任意自然语言逻辑。

“修改查询条件”在副本中编辑完整条件。组内全部满足，组间满足任意一组。数值使用来源基本单位并保留字符串精度；集合比较每行一个值，空值比较不填写数值。删除全部组表示清除附加字段筛选，保留公司、报表、展示方式、排序及每页条数，页码回到 1。空的条件组无效。关闭弹窗不修改原卡片。

编辑提交绑定当前成功查询的服务端引用，完整条件与引用共同进入实际 HTTP 请求。新轮次、其他标签页更新、权限变化或失败焦点会使旧操作失效。服务端把已经核对的完整编辑作为独立结构化输入提供给三个模型阶段，避免仅有显示文字时丢失新条件。编辑仍执行真实目标判断、完整规划、业务预检和独立复核；两份计划都必须完整保留提交的条件，不能把查询编辑转为派单。

模型需要澄清且存在 2–8 个可核验候选时，可提供公司、报表、字段或枚举按钮。标签来自服务端目录；字段和枚举绑定具体数据域、公司及报表，枚举不能从其他公司词典拼凑。点击后将原问题与已经完成的选择作为结构化状态交给三个模型阶段；后续澄清累计保存已解决维度，原问题中的“尚未决定”不能再次覆盖当前选择。程序同时核对选择没有被替换，也不能重复索取相同维度的选择，其他真实歧义仍可继续澄清。选择不等于确认派单。旧按钮及词典变化后的按钮被拒绝。

任务已明确而参数尚待选择时，目标判断保留原业务目的，规划阶段澄清参数；不能将参数选择改成通用帮助。日期契约区分绝对公历年月日、相对时间与财年口径，明确年月不由当前月份替代。这些约束仍须通过真实回放验证，不能据提示文本本身声称识别无误。

查询对象与旧预览的准备规则分别传入模型。旧预览被其他话题打断时，重新展示限制仅适用于再次使用该预览；可用的新查询对象可以由执行层重新核验后准备清单。两条路径都保留当前权限、资格、版本及最后的用户确认，不能因词典发布或历史对象失效而绕过检查。

规划根对象有 `route`、`query`、`followUp`、`clarification`、`removedFilters`、`dispatch`、`clarificationOptions` 七个必填字段，不适用字段显式为空。SSE 与持久历史均包含 `semantic_clarification` 卡片；业务查询卡片附带 `interpretation`。结构化请求中的额外字段、数字转字符串、缺少必填字段均拒绝。

## 评估工具与证据

`tools/test-semantic-quality.cjs` 对已经启动的授权本机隔离夹具回放，不创建库、不重置来源、不确认派单。夹具仍须先取得本轮数据库授权，使用既有 `AssistantBrowserAcceptanceTest`，启用 `ASSISTANT_BROWSER=true`、`SEMANTIC_P0=true` 并配置真实模型环境。它在限制访问的忽略目录提供 `ready.json` 与临时验收账号文件；运行结束由夹具清理自身测试库。

```powershell
node tools/test-semantic-quality.cjs --runtime-info .runtime/p0-run/ready.json --credentials .runtime/p0-run/admin-credentials.json --corpus tools/fixtures/semantic-quality-regression-v2.json --output .runtime/p0-run/regression-first.json
node tools/test-semantic-quality.cjs --runtime-info .runtime/p0-run/ready.json --credentials .runtime/p0-run/admin-credentials.json --corpus tools/fixtures/semantic-quality-regression-v2.json --output .runtime/p0-run/regression-second.json
node tools/test-semantic-quality.cjs --runtime-info .runtime/p0-run/ready.json --credentials .runtime/p0-run/admin-credentials.json --corpus tools/fixtures/semantic-quality-temporal-intent-v1.json --output .runtime/p0-run/temporal-intent-first.json
node tools/test-semantic-quality.cjs --runtime-info .runtime/p0-run/ready.json --credentials .runtime/p0-run/admin-credentials.json --corpus tools/fixtures/semantic-quality-reserve-v1.json --output .runtime/p0-run/reserve-first.json
node tools/test-semantic-quality.cjs --runtime-info .runtime/p0-run/ready.json --credentials .runtime/p0-run/admin-credentials.json --corpus tools/fixtures/semantic-quality-logic-v1.json --output .runtime/p0-run/logic-first.json

```

路径是已经启动夹具的输出目录示例，不是生产启动命令。每次真实重跑使用新证据文件，禁止覆盖旧失败。真实模型配置缺失、不可用或输出不可靠时分别保存配置/调用失败、澄清和恢复证据，不能用预置结果替代。

评分先从独立报表页读取事实，再核对语料的动作、数据域、公司/报表、条件语义、金额、总数、展示身份及澄清候选。日期期望依据该轮实际参考时刻和词典时区计算。统计区分明确查询首次成功、修正次数、预期/非必要澄清、模型调用失败、校验失败及基础设施故障；按阶段报告 p50/p95/p99 与计量覆盖率。小样本分位数只是该批描述，不能推导生产 SLO。

回归、相邻边界补充和预留集分别版本化，记录语料、评分器、源码、词典及来源数据摘要。当前语料均由工程编写，未经业务方独立审核。字段候选和筛选条件共用明确来源字段的等价比较，公司、报表及枚举身份仍严格比较；修订评分器后保留原始失败，不把旧评分与新评分直接混算。预留集一旦用于修复，后续结果就属于已见样本回归。不同语料、来源、评分器、日期口径或缺失/重复用例的结果不能直接比较；相同基线的代码、模型或词典变更分别列为实验变量。

数据库/状态机回归、前端逻辑、真实模型与认证 HTTP MCP、浏览器交互分别记录。门禁为 `node tools/check-comments.cjs`、`node tools/check-docs-real-model.cjs`、工具测试及授权后的 `tools/test-regression.ps1 -AllowIsolatedDatabases`。静态门禁和前端测试不代替真实浏览器验收。
