# 通用业务助手

当前助手在同一会话中提供报表查询、派单记录查询、工单进度和总结，并保留 V1 派单规划。链路为 `real,mcp`、`agent.semantic.mode=active`，真实模型使用原生 JSON Schema、thinking 关闭；业务事实来自带服务认证的 HTTP MCP。RAG 暂不引入。

页面工具栏、手工派单记录抽屉及运营治理的用法见[工作台操作与运营治理](工作台操作与运营治理.md)。对话查询的派单记录与报表页手工记录入口范围不同。

## 使用方式

| 要做的事 | 示例 | 返回依据 |
| --- | --- | --- |
| 看报表业务数据 | 查询 A 公司的销售报表数据，金额超过五万元 | 授权来源记录，包含已派单和不满足派单规则的记录 |
| 排序与翻页 | 按金额从高到低排，每页两条；下一页 | 相同筛选条件和稳定排序，卡片总数代表全部匹配 |
| 数据总结 | 总结这批销售数据的金额和状态分布 | 服务器精确统计，按已声明币种分别合计 |
| 单条派单资格 | 查一下销售报表服务器的数据；这条数据符合派单条件吗 | 唯一记录的当前状态、生效规则和实际字段值；只读核验，不生成候选或清单 |
| 派单记录 | 查询失败的派单记录，按公司汇总 | 持久清单条目；普通用户仅看本人，管理员仍受公司和报表权限约束 |
| 工单进度 | WO-DEMO-001 到哪个环节了，谁来处理 | 业务接口返回的当前环节、处理人和完整流程 |
| 工单总结 | 总结 A 公司全部工单；只看待审批的 | 全部匹配工单的状态分布、当前审批人和金额 |
| 准备派单 | 查一下我有哪些可以派单 | 原 V1 派单规则、预览、勾选及待确认清单流程 |

来源字段名称、类型和说明来自授权目录，支持有界 AND/OR 条件、空值判断、数值和日期比较、文本包含等。未声明字段、任意 SQL、跨数据域关联计算、催办、审批或修改工单会澄清或拒绝。详情匹配多条时要求明确编号，不能猜测“某一条”。

“报表名 + 字段值 + 的数据”可以省略字段名，由真实模型依据目录字段含义识别产品、费用类别等筛选。能够确定字段时保留该值；存在歧义时澄清，不把未理解的业务值直接丢弃后返回整张报表。无条件草稿还会核对本轮实际读取的字段值：用户明确说出某值的数据或明细，而当前授权结果中已存在该字段值时，将遗漏证据交回模型修正；校验不会自行拼接查询，也不会把当前页没有出现的值伪称为已验证事实。

对单条记录询问是否符合派单条件时，使用上一成功查询的明确记录引用，业务服务重新读取其当前事实。核验同时检查报表是否启用派单、记录是否未派单及当前生效规则，不把“未派单”本身当作符合条件。具体公司规则优先于通配规则，并遵守规则生效时间和版本；结果展示结论、规则说明及实际参与求值的字段。已派单、未命中规则、没有适用规则分别说明原因；规则计算失败明确告知暂时无法判断。多条记录中的含糊指代须澄清，不扩大为全部报表候选。核验不继承可能遮蔽当前状态的旧金额或状态筛选，也不会创建预览、修改勾选或生成清单。

连续追问只引用上次成功查询及已展示行的序号；翻页后序号沿用列表中的实际位置。独立新查询重新确定范围。失败不会把不完整读取当成成功，也不能以含糊追问沿用过时查询。

查询卡片的翻页和工单“查看进度”按钮会发送明确的连续对话请求，经过真实模型规划及业务读取；它们不是浏览器本地切片。只有最新查询卡片可继续翻页，历史卡片保持原查询时点的快照。

当前页已展示的标量字段与编号一同作为追问依据，便于根据产品、费用类型等明确引用记录；未展示的行不进入指代上下文。询问如何确认、能否审批属于功能说明，不能被当作执行请求。明确公司范围和数值区间另做一致性校验，防止遗漏公司或把区间上下界错误地取并集。

上一成功查询另提供完整匹配条数、已展示条数及是否已完整展示的标记。第一页确实包含全部匹配记录时，可以据此定位唯一最高或最低记录；总数未知、分页未展示完整或查询失败时不能把当前页当作全集。完整客户名称查找使用精确相等条件，明确要求包含或局部名称搜索时才使用相应运算。

成功查询的零条结果仍有明确范围，继续询问总额、数量或分组时可按原条件返回零值/空分组。零条结果不等于查询失败，不要求用户重复给出原范围。

切换业务域时，新查询的报表限定须有本轮依据，不能把已结束的报表话题带入工单过滤。按极值展开单笔详情时，需要依据已展示事实给出稳定标识；仅排序后取第一条不能证明对象唯一，完整读取和多条歧义保护仍由业务服务执行。

查询草稿会先经过认证 HTTP MCP 的只读校验，匹配多条等确定性错误可用于最多两次草稿修正。成功结果在本轮直接用于展示，失败草稿不写卡片、不更新成功查询上下文。追加状态条件不能静默移除未撤销的日期等其他字段限制；无字段条件时使用空条件数组，不能生成空的 AND 组。

追问中明确撤销旧条件时，模型计划使用 `removedFilters` 记录被撤销的字段及本轮连续原文证据；未被撤销的其他字段继续保留。此结构只属于规划协议，不改变业务查询接口，也不能用历史原文或模型解释代替用户依据。普通只读查询后，模型修正也不能把被拒绝的建单改成无明确范围的旧预览刷新。

会话分别记录最近尝试和持续业务焦点。帮助或澄清不清除原来的查询/派单焦点；派单预览中的选择操作不能因出现字段条件被静默改成普通查询。路由校验只拒绝丢失选择含义的草稿，并使用同一有界草稿修正预算；它不按词语生成意图或执行关键词回退。

普通查询不变更现有派单预览、排除集合或清单。尝试普通业务查询后，即使读取失败，也需要先明确查询可派单范围，再调整候选或生成清单；普通查询中的“这些”不能隐式套用旧预览。确认派单始终使用原卡片和独立确认接口。

## 工单的演示范围

本机工单提供者使用固定环节和固定演示审批人：提交登记、部门审批、财务复核、业务处理、归档。固定示例覆盖待审批、处理中、已完成和已驳回，另有 B 公司示例用于权限验证。它们标注为“固定演示示例”，不是实际派单记录。

当前用户有权查看的成功派单条目具有稳定请求号时，可以映射为 `WO-<请求号>` 工单，来源标注为“实际演示派单关联”。派单成功只证明提交结果，因此关联流程停在首个审批环节，不自动变成审批成功。

查询不会推进流程。终态工单没有当前处理人；未来环节的审批人不计入当前待办。工单详情和总结由接口事实确定性生成，模型不编造办理原因、审批意见或完成时间。真实工单系统尚未接入，后续替换 `WorkOrderProvider` 实现并进行实际接口验收。

## 数据、统计和权限

- 报表全部状态读取使用配置适配器的 `dataRowsAfter`，未实现该能力的自定义适配器明确拒绝，不以待派单子集代替。
- 当前实现每轮在限定公司和报表范围内有界读取，再统一筛选、排序和统计；默认最多扫描 100000 条、120 秒，保留事实另外限制为 16 MiB。条件筛选尚未普遍下推来源数据库。超限时整体失败，可缩小公司或报表范围，不能把截断集合当作全部数据。
- 列表每页最多 50 条；金额和长标识按字符串传输，金额使用精确十进制。没有声明币种的金额不参与合计。本仓库三张演示报表在业务服务配置中明确声明 CNY；外部报表应由其来源字段或可信配置声明单位。
- 查询前由当前目录展开可见报表，业务服务再次检查租户、公司、报表及派单归属。身份由服务器注入，模型不能提供用户或管理员标记。
- “我创建的派单”使用服务端计算的 `createdByMe` 条件，按当前认证标识匹配，不把“我”当作姓名。同名用户不会相互匹配，管理员查询本人时也只返回本人记录。
- 查询没有匹配行仍保留其业务数据域；继续筛选、分组或翻页不能静默切换成另一类对象。明确发起另一类对象的查询时，作为独立查询处理。
- 卡片持久化查询时点、实际范围、当前页和完整统计；刷新恢复历史快照，不把旧时点当作实时数据。会话保留曾查询报表的范围并集，权限变化后拒绝展示该会话，需新建会话重新查询。
- 数据库继续使用 `report_demo`，本次未新增业务表或迁移，不清库、不重置已派单状态。固定工单资源不写回来源表。

## 实现与验证入口

`ModelAssistantPlanner` 先判断本轮业务查询、派单、帮助或澄清。只读查询通过 `AssistantCodec`、`BusinessQuery` 和 HTTP MCP `business_query` 执行；派单进入原 `ModelIntentParser`。正常无修正的派单文本经过两个模型规划阶段；两层各最多修正两次，不能把两个阶段理解为整轮严格只有两次 HTTP 请求。实际延迟和费用须按运行记录评估。

```powershell
./tools/test-business-assistant.ps1
./tools/test-business-assistant.ps1 -CorpusPath tools/fixtures/business-assistant-holdout.json
./tools/test-business-assistant.ps1 -CorpusPath tools/fixtures/business-assistant-eligibility.json -EvidencePath .runtime/business-assistant-eligibility.json
node tools/check-comments.cjs
node tools/check-docs-real-model.cjs
```

以上回放使用已准备的 A 公司演示账号，创建会话并读取数据，不确认派单。报表结果与独立报表页读取比较，工单与固定业务示例比较；真实模型、HTTP MCP、程序回归及浏览器验收分别取证。整体数据库回归仍须获得本轮授权后运行 `test-regression.ps1 -AllowIsolatedDatabases`。

初版实现与约定范围验收见[实现与验收报告](review/通用业务助手实现与验收_2026-10-07.md)，保留当时 843 项程序测试通过、11 项条件跳过及 90/90 真实模型回放的历史证据。最新[整体回归与多轮对话验收](review/整体回归与多轮对话验收_2026-10-07.md)记录 880 项完整程序回归通过、180 轮真实模型回放及一处评分误报复核、浏览器与服务重启恢复。中间失败均保留；有限用例不代表任意自然语言、真实 ERP、正式外部认证、生产容量和灾备已经验收。
