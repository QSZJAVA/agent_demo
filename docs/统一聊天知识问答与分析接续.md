# 统一聊天知识问答与分析接续

聊天入口通过真实模型的任务意图、完整计划和独立复核，选择普通业务查询、知识问答、有限多步分析或待确认派单。运行基线为 `real,mcp`、`agent.semantic.mode=active`、真实模型认证及 HTTP MCP 业务服务。模型只能选择授权范围和白名单动作，程序负责事实计算、版本核对与执行边界。

## 使用方式

- “解释 A 公司销售报表的派单条件，并给出依据”：在明确公司和报表内检索当前发布知识、规则、目录和业务词典。
- “分析 A 公司销售报表，按产品分组后取金额最高的两组”：发起有限只读分析，结果作为聊天中的任务卡片显示。
- 先完成 A 公司单张报表查询，再问“只分析刚才这些，按产品汇总金额”：使用原完整查询快照。分页只影响展示，分析不会把当前页误当全部匹配事实。
- 任务卡片展示状态、回答与引用，点击“查看步骤和完整依据”进入分析工作区。取消任务是独立明确操作；离开聊天页不会自动取消已提交的子分析。

知识缺失、模型不可靠、范围歧义或计划超出预算时，系统说明缺失和澄清原因；没有关键词或固定语义样本接管。派单仍先准备清单，由用户检查并点击确认。真实工单、外部 ERP、正式认证及生产容量、灾备准入未纳入本轮。

## 三种读取模式

| 模式 | 允许读取 | 约束 |
| --- | --- | --- |
| `KNOWLEDGE_ONLY` | 当前范围的知识与规则依据 | 不接收业务快照，不查询当前业务记录 |
| `SNAPSHOT_ONLY` | 明确选定的原完整快照、分组、排名、明细展开及知识 | 必须绑定原快照，禁止重新查询和两集合对比 |
| `CURRENT_DATA` | 当前受控查询与原有有限只读图 | 只有显式提供原快照时才可引用它参与比较 |

模式参与请求哈希、模型 JSON Schema、全图检查、逐步执行和恢复。独立分析页也必须明确选择模式。最新请求和持久协议不兼容历史结构；旧本地数据不能靠补默认模式继续执行。

原查询接续只允许当前成功、完整、单公司单报表的查询焦点。来源引用由快照标识、查询轮次和权限版本共同生成，不由模型提供实际 snapshotId。来源过期、撤权、查询失败、焦点变化或范围不一致时拒绝接续；不能静默改查当前数据。知识或当前数据的新问题可按用户明确的新范围另行规划。

## 丢响应与刷新恢复

浏览器在发送前按用户和登录会话摘要保存完整载荷及请求号，并回读确认存储成功。查询条件、澄清选项和预览排除集合不能截断；本地存储失败或超出预算时阻止发送。身份切换、隐藏页面和迟到响应均有守卫。

服务器先在同一事务创建会话和 `chat_turn_receipt`，再调用模型。相同键、相同完整输入回放原轮次；键冲突返回409。首次输入中的空会话标识仍是原载荷的一部分。

| 回执状态 | 含义与恢复 |
| --- | --- |
| `RECEIVED` | 已接收但未开始；明确核对可开始原问题 |
| `PLANNING` | 原问题正在处理；读取状态不重新调用模型 |
| `READY` | 完整方案已独立复核并冻结；明确核对可重核原权限、资料、配置及快照后提交 |
| `SUBMITTED` | 已原子关联唯一分析任务；回放同一任务 |
| `COMPLETED` | 普通查询、帮助、澄清或派单准备的处理已结束；读取原会话 |
| `INTERRUPTED` / `FAILED` | 原轮次已中断或失败；查看已保存事实，再明确发送新问题 |

首次或末尾响应丢失后，刷新仅 GET 原回执，不自动 POST。只有点击“核对本次提交”才使用原键、原完整载荷提交核对。已提交子任务使用 `analysis-<服务端requestId>` 防重，任务创建、回执关联和卡片事件在同一个短事务提交。处于 PLANNING 的超时轮次不会再次解释原文；READY恢复不会重新调用统一规划器。

固定资料、权限、快照或执行配置失效时，READY明确结束为FAILED并说明原因，避免无限核对同一失效方案。GET仅投影失败且保持只读；原键POST核对才持久化原回执终态，迟到核对不会改写后来轮次的会话状态。服务暂不可用、并发配额或租约竞争保留原方案供稍后核对。普通轮次完成后还需等待可靠消息全部投影：回执的historyReady为false时保留原请求及已收到内容，只轮询GET；为true后按持久消息标识补读完整历史，不按文字内容合并消息。

回执可核对期为24小时。到期清理可信正文和恢复指纹，保留最小防重身份；会话清理也保留该身份与删除墓碑，原空会话请求不能重新创建任务。删除会话后，关联分析立即不可读取和继续执行，其证据由留存服务分批清理。

## 答案与权限

聊天中的分析卡片只持久保存 requestId、runId、mode、companyCode、reportId 五项引用。回答和引用原文每次从分析服务重新读取，并核对本人、公司、报表、知识版本、模型配置、原快照和会话删除状态。历史卡片还验证会话—轮次—任务关系及稳定子请求号；关联损坏、失效或撤权时清空旧内容并中性展示。

可见的终态分析卡片每30秒重新核对；到期先撤下旧答案，读取失败不会继续显示过期内容。隐藏或销毁页面时停止轮询，重新显示后重新授权读取，不因此调用模型或重建任务。

知识和分析范围纳入整个会话的历史权限并集，不能只遮挡卡片却让普通助手文本暴露已撤销的业务事实。分析问题和已完成步骤的恢复仍遵循当前版本运行期正确性，不代表支持旧版本数据迁移。
