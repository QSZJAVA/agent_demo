# 上下文工程：第三阶段

日期：2026-10-06（Asia/Shanghai）。本文是当前上下文工程的设计与操作说明，承接异常调查 Agent 的只读工具循环、任务持久化和评估体系。

## 当前范围

继续使用当前 Java、Spring AI 和 Vue 技术栈，以 `real,mcp`、`agent.semantic.mode=active` 为基线。模型解析来源为 `MODEL`，业务核对经具有服务认证的 HTTP MCP 执行。真实外部认证系统、外部 ERP、生产容量和灾备验收仍待完成。

当前调查提供六个只读工具：

| 工具 | 职责 |
| --- | --- |
| `investigation_plan_summary` | 查询绑定清单的快照概要 |
| `investigation_plan_items` | 分页查询本次调查条目 |
| `investigation_rule_snapshots` | 查询条目执行时的规则快照 |
| `investigation_execution_events` | 分页查询执行事件 |
| `investigation_dispatch_lookup` | 通过原请求号核对远端业务结果 |
| `investigation_evidence_read` | 按当前运行的 E 编号回读已取得的业务证据 |

报告包含业务结论、证据引用和待查事项。调查不执行派单、修复或重发；后续业务操作继续走原有权限、用户确认、幂等和执行版本检查。

## 结构化上下文笔记

`InvestigationContext` 在完整工具调用轮次之间检查逻辑消息 UTF-8 体积。默认超过 24576 字节时尝试整理，仅在整理后的消息更小时替换原历史。保留系统约束、原始问题和最近完整的一组工具调用及全部对应结果，避免协议孤儿消息。

笔记从当前运行已落库的证据确定性生成，不把模型摘要当作事实：

- 保留执行版本、证据编号、条目范围、来源类型和截断标识。
- 保留所有已取得的条目状态及远端核对结果，包括先 UNKNOWN 后 SUCCESS 的两次观测。
- 保留缺失、完整性、分页游标、核对次数、剩余工具预算和收集结束原因。
- 省略旧规则及事件的长说明，需要时通过证据回读工具取得完整有界内容；省略不等于缺失。

`context-v2` 笔记还提供 `availableEvidence` 目录，按证据取得顺序列出 E 编号、来源类型、条目范围和详情按需读取标记。模型回读前须区分 `EXECUTION_EVENT` 与 `RULE_SNAPSHOT`；回读回复通过 `sourceType` 明确实际来源，避免把规则详情误作事件详情。目录本身不包含新增事实，也不授予额外查询权限。

首次回读某份证据算作有效进展；重复相同回读仍受无进展限制和总工具预算约束。证据回读不生成新证据编号，不能读取其他运行或尚未取得的证据。

`CONTEXT_COMPACT` 控制步骤保存整理前后体积与笔记；模型步骤记录输入字节数和策略版本。报告阶段同样使用确定性事实投影，不携带完整历史聊天。

## 状态、权限和有效期

笔记只在当前调查认领轮次内使用，不跨账号、任务或会话继承。工具调用和报告生成仍复核任务执行权、当前业务权限及来源状态；取消、超时或失租后不得回写迟到结果。

页面刷新只读取已有任务。进程中断继续按原调查状态机结束为中断，不自动重放真实模型请求；重新分析由用户显式发起。本阶段不宣称实现跨进程检查点续推理。

目标阈值不是强制截断。若系统约束、必要事实和最近完整工具结果仍超过实际请求上限，明确返回预算失败，不删除约束或伪造报告。传输层独立检查包含工具定义与 Schema 的实际 HTTP 请求体积。

## 配置与验证

`agent.investigation.context-target-utf8-bytes` 默认 24576。运行配置记录该预算及 `contextVersion`，评估归档保存配置和编译产物指纹。评分器版本更新为 5，避免将不同报告契约的批次混用。当前任务集为 40 个业务调查场景，其中 16 个保留场景。

上下文定向回归：

```powershell
.\backend\mvnw.cmd -f backend/pom.xml '-Dtest=InvestigationContextTest,InvestigationAgentTest,InvestigationProtocolTest' test
```

完整回归：

```powershell
.\tools\test-regression.ps1
```

需要真实模型评估时使用既有 `tools/test-investigation-live.ps1`，从已忽略的本机配置读取模型端点及凭据。配置缺失或真实端点不可用时保留失败，不改用其他语义来源。

真实模型上下文专项使用独立入口与归档：

```powershell
pwsh -NoProfile -File tools/test-investigation-live.ps1 -Context -Repeats 3
```

专项保留默认 24576 字节整理阈值、6 轮收集和 16 次工具预算；以四项各 20 条长事件的合成事实触发整理，模型请求全部由真实端点生成。用户任务明确要求分页读完事件，并在看到实际程序笔记后回读早期事件证据。这是用户指定流程的上下文链路验收，不衡量无提示的自主工具选择能力，也不代表真实 HTTP MCP 或业务库验收。

归档位于 `backend/target/investigation-context-evaluation/run-*`，首次调用前保存配置，每个题次开始与结束更新检查点，逐轮记录逻辑请求、工具调用和用量。通过条件包括：80 条事件完整读取、实际发生缩小的 `CONTEXT_COMPACT`、真实模型收到结构化笔记、模型在整理后按 E 编号回读输入中已省略的事件详情、下一次真实模型请求确实携带回读结果、工具消息正确配对及最终四项状态通过独立评分。没有整理、只回读仍在上下文中的详情或只给出正确分类均不能算专项通过。

普通回归会关闭 `INVESTIGATION_CONTEXT_LIVE`；专项不会在缺少模型配置时改用其他解析来源。重复次数独立归档，失败保留，不由后续成功覆盖。

工具分页按完整序列化响应检查 UTF-8 体积，包含数据、分页游标、事件总数、证据编号和观察时间。编号按接口允许的最长 E 编号保守预留最多五个额外字符；不再固定扣除 512 字节。`max-tool-result-utf8-bytes=512` 仍是允许的配置，可容纳的单条或空页正常返回，真正无法容纳的单条在保存证据前明确拒绝。

本次仅调整代码、测试和当前文档，没有修改表结构、重建日常 Demo 库或清理运行数据。历史评审保留其日期、版本和原始证据范围，不代表当前版本已验收。
