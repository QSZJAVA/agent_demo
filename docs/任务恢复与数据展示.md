# 任务恢复与数据展示

当前运行基线为 `real,mcp`、`agent.semantic.mode=active`、真实模型接口及认证 HTTP MCP。任务历史读取使用已保存的执行状态，查询语义仍由真实模型规划和独立复核。

## 我的任务

左侧“我的任务”集中展示本人已提交的手工派单、确认派单、失败项重试和结果核对任务。离开页面、刷新浏览器或在另一设备登录后，可以重新查找这些任务；访问时按当前租户、公司和报表权限复核。

1. 按“排队中、执行中、处理完成、任务失败”筛选。刷新和更换筛选会从最新一页开始，“更早任务”读取下一段历史。
2. 点击关联的“查看清单”，核对当前清单状态、逐条结果和失败原因。清单超过 50 条时继续翻页，金额按精确十进制展示。
3. 本人清单可打开完整追溯。管理员代处理产生的任务通过运营只读入口查看原操作者的清单，后续处理进入运营治理；管理员仍受当前业务数据权限限制。
4. 加载失败会保留页内错误和“重试加载”。读取任务、查看清单和刷新结果不会生成新的派单请求。

“处理完成”表示该任务的处理过程结束，业务条目可能存在失败或待核对结果，应以关联清单为准。结果超过保留期时明确显示不可用；手工派单任务的清单关联来自所保存的结果，结果到期后可能无法从任务历史取得关联。

P1 的“任务与站内提醒”同时展示待确认清单、需处理异常、派单任务、异常调查及查询导出。尚未提交执行任务的清单也能在刷新后找回；本人详情支持显式确认、结果核对和确认后重试明确失败项。提醒按对象及状态版本去重，已读状态持久保存；查看历史调查只恢复所选运行。完整导出及工作区操作见[查询工作区与日常分析](查询工作区与日常分析.md)。

历史按创建时间和任务标识稳定倒序分页。每页最多 50 项，服务端每次最多扫描 200 条候选；当前权限过滤后可能出现空页且仍有后续游标，此时可以继续查看更早任务。页面不把这一段空结果描述为全系统没有任务。

## 金额与报表恢复

普通报表、派单预览、清单、历史卡片和追溯中的金额按十进制字符串传输并展示，后端业务计算继续使用 `BigDecimal`。页内合计使用精确十进制运算，例如 `90071992547409.93` 加 `0.01` 等于 `90071992547409.94`。

缺失金额显示为破折号，异常格式明确标出。合计说明缺失或异常金额数量；这些值不会自动当成零。普通计数和执行版本仍使用整数契约。

销售、应收、费用报表共用分页恢复逻辑。读取失败时页面保留错误和重试入口，只有成功读取到空集合才显示零条数据。切换页面、筛选或登录上下文后，较早响应不会覆盖最新结果。

## 只读接口

`GET /api/dispatch/jobs/history` 接受 `before`、`status`、`size`，返回 `rows` 与 `nextCursor`。游标绑定当前身份和筛选；更换筛选需从首页读取。列表提供任务类型、状态、说明、创建及更新时间、结果可用性与已授权清单关联，不返回原始提交负载、幂等键或完整业务结果。

普通清单摘要和条目继续使用 `/api/dispatch/plans/{planId}` 及其 `/items`。管理员任务的清单摘要与条目使用 `/api/operations/workbench/{planId}` 及其 `/items`，保存真实管理员的读取审计；普通清单接口的归属校验没有放宽。

本轮优化规划见[整体评审与优化计划](review/整体评审与优化计划_2026-10-11.md)。实际测试结果按程序回归、数据库／HTTP MCP、真实模型和真实浏览器分别归档。
