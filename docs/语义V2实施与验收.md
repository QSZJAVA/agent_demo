# 语义 V2：统一模型解析与确定性业务编译

## 当前状态

自由文本入口已改为统一模型解析。原 `DomainIntentParser` 及其语法命中测试已移除，替换为模型路由、协议边界、状态原子性、兼容和业务级回放测试。真实模式没有关键词解释兜底；mock 模式只读明确列出的固定样本，其余澄清。

本轮未重启或发布正在运行的服务。V2 真实模型验收尚未完成：当前环境和项目本地配置没有可用的 `LLM_API_KEY`。不得将离线模拟样本的通过率表述为模型准确率，亦不得引用 V1 的 19/19 领域语法回放或历史 29 项 HTTP 验收作为 V2 通过证据。

## 业务指令

V2 模型输出：

```json
{
  "version": 2,
  "action": "PREVIEW",
  "scopeChanges": [
    {
      "target": "REPORTS",
      "operation": "REPLACE",
      "mentions": ["销售报表"],
      "evidence": "只查销售报表"
    }
  ],
  "restrictions": [
    {
      "action": "PREPARE_DISPATCH",
      "scope": "THIS_TURN",
      "evidence": "不要派单"
    }
  ],
  "clarify": "NONE"
}
```

- `scopeChanges` 最多 8 个有序修改，目标为 COMPANY、REPORTS、RECORDS。
- 不修改的目标不输出；不在 JSON 中输出 KEEP。CLEAR 必须是用户明确清除，不等于省略。
- 公司最多一次 REPLACE（单家公司）或 CLEAR；多家公司需澄清。
- 报表按顺序 REPLACE/ADD/REMOVE/CLEAR；所有实体解析成功才提交请求范围。后续操作失败不会部分应用前面的操作。
- RECORDS 表示排除集合：ADD 为排除，REMOVE 为恢复。记录操作必须放在范围修改之后，针对最终预览执行；整组成功才提交排除集合。
- `restrictions` 表达本轮禁止的动作，不继承到下轮。请求动作与禁止动作冲突时拒绝整个指令。
- HELP、CANCEL_PLAN、SHOW_RESULT、CLARIFY 不携带范围修改；澄清只标记未解决条件，不修改已经生效的范围。
- 模型动作枚举不包含 EXECUTE/CONFIRM；准备派单只能产生待确认清单，确认仍为确定性 REST 调用。

不支持任意 SQL、金额/日期筛选、任意多动作程序或同时多次查询。提示词要求不能完整表达的请求进入澄清，不允许丢弃后半句再执行前半句。

结构校验、原文证据、实体覆盖和权限校验只能约束输出，不能证明模型对原文的理解一定正确。具体端点的语义准确率必须独立测量。

## 实现责任

| 模块 | 责任 |
| --- | --- |
| `SemanticIntentParser` | 全部自由文本交给同一个 ModelIntentParser，没有语法短路 |
| `ModelIntentParser` | 无工具解析，温度 0；协议/原文/报表覆盖失败最多修复一次，仍失败则澄清；默认 2400 输出 tokens，thinking 模式 4096；当前输入的敏感实体使用可逆临时占位符，服务端恢复后再定位 |
| `intent-v2.schema.json` / `IntentCodec` | 原生 Schema 可选；服务端始终拒绝未知字段、版本错误、标量强转、无效枚举、无原文证据、操作/禁止冲突和不支持的指令顺序 |
| `SemanticPlanner` | 目录实体解析与权限验证；先在草稿上完成所有范围操作，成功后一次提交 desired；失败标记 unresolved，禁止后续省略条件退回旧范围 |
| `SemanticConversationService` | 复用既有预览、清单、版本、配额、租约及确认边界；所有记录选择操作成功后提交；协议失败先标记范围未解决；结束 SSE 前释放会话及配额租约 |
| `DialogueStore` | 读取 V1 pendingIntent 时转换为 V2；desired/effective、预览、选择、租约和审计不清空 |
| `SemanticEvaluation` | 离线/真实模型共用业务结果 oracle，只处理合成数据，不访问业务数据库或调用派单网关 |

目录词典只提供候选名称和覆盖检查，不决定自然语言动作。报表选择、勾选、确认和取消按钮仍复用原 REST 接口，未增加框架或依赖。

## 回放和测试

`replay-corpus.json` 保留原 19 轮；`business-corpus-v2.json` 新增 32 轮，共 51 轮。覆盖：

- 查询动作的否定与报表排除的区别，不同语序及同义表达。
- 一轮内替换、追加和移除；操作顺序对应最终集合。
- 同一预览中的排除与恢复；后续记录无法定位时不得部分提交。
- 禁止条件仅本轮有效，下轮明确要求生成清单时可创建 PENDING 清单。
- 歧义、未知指代、不支持条件、冲突动作的澄清。
- 公司拒绝后的省略继承、显式纠正、模型故障后禁止复用旧范围。
- V1 持久状态读取兼容、模型无工具/原生 Schema 请求契约。

离线结果写入 `backend/target/semantic-v2-offline-evaluation.json`，明确标记 `parserSource=MOCK` 和 `modelAccuracyMeasured=false`。模拟输出用于验证服务端行为，不用于证明自然语言解析正确率。

```powershell
# MySQL/Redis 隔离库全量回归；不操作共享演示业务表
./tools/test-p2.ps1 -BackendOnly

# 真实模型验收：在本机环境变量或私有 tools/env.local.cmd 配置 LLM_*，不要提交密钥
./tools/test-semantic-live.ps1
# 端点确认支持时才添加 -NativeSchema 或 -Thinking；-Model 可指定模型
# 额外 24 轮新表达（不参与 mock 样本）
./tools/test-semantic-live.ps1 -NativeSchema -Corpus business-additional-corpus.json
```

真实模型评估只使用合成语料，检查动作、最终报表集合、公司、排除项、禁止条件与拒绝/澄清结果；所有成功解析必须来自 MODEL。`-ModelOnly` 保留为旧脚本参数兼容，V2 始终调用模型。结果写入 `backend/target/semantic-live-evaluation.json`。

V2 初始实现阶段的历史验证：全量隔离回归 612 项，597 通过、15 按环境开关跳过、0 失败；随后补充边界断言的 SemanticV2Test（12 项）和 SemanticIntegrationTest（11 项）定向回归全部通过，二者与全量测试有重叠，不能相加。51 轮离线业务回放全部通过。初始阶段未配置真实模型密钥，以上数字不代表后续修复版本。

## 上线与回滚

1. 对部署时选定的模型、端点、Schema/thinking 配置跑真实回放，检查逐轮失败及误扩大范围，不能只看平均通过率。
2. 先在测试环境部署 V2；用实际业务语料补充独立验收集，再验证 HTTP、页面恢复与业务结果。
3. 通过后再小范围启用。当前 active 配置在新版本中指向 V2，但本轮没有发布或重启已有进程。
4. 显式 `SEMANTIC_MODE=legacy` 保留历史入口，不能在 V2 解析失败后自动回退。V1 二进制不保证能读 V2 pendingIntent；需要回退二进制时按备份/版本兼容方案处理，或使用新会话，不回删 Flyway 迁移。

后续已补普通报表分页、前端勾选恢复失败保护、预览刷新排除项保留和 Vite 依赖升级。真实认证仍待对接，真实业务派单按 [MCP 契约](MCP派单接入契约.md) 在下一阶段接入。真实模型结果应以对应版本的逐轮评估文件和验收报告为准。
