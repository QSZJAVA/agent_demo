# 通用业务助手实施计划

状态：2026-10-07 已完成本计划约定的实现与验收，逐项结果及失败修复过程见[实现与验收报告](review/通用业务助手实现与验收_2026-10-07.md)。基线为 V1 / 1.0.0、`real,mcp`、`agent.semantic.mode=active`，真实模型解析与带服务认证的 HTTP MCP。RAG 暂不引入，前端依赖及账号生命周期范围保持不变。

## 目标与验收边界

统一对话入口同时支持报表数据查询、派单数据查询、工单进度查询、工单总结及既有待确认派单。普通数据查询包含已派单和不满足派单规则的数据，不能把“查询报表”自动解释成“查询可派单”。查询不改变预览选择、生成清单或执行写入。

查询提供目录声明的字段条件、公司与报表范围、分页、排序、数量与金额汇总；允许围绕上一查询继续筛选、翻页和查看某项详情。列表、汇总及流程事实必须来自同一组已授权数据，明确查询时点、完整性和演示来源。范围不清、字段不支持、权限变化或预算耗尽时明确失败或澄清。

工单由业务服务提供独立只读接口。本机采用明确标注的固定演示流程、固定审批人和多状态示例；实际演示派单成功请求可映射到固定的初始审批流程。固定样例不冒充真实派单记录，不回写来源报表，不模拟自动审批成功。真实工单系统接入后替换业务服务内的工单提供者，助手不直接读取外部数据库。

## 实施顺序

1. 新增通用业务请求协议与真实模型解析入口，区分业务查询、派单操作、帮助和澄清；复用当前会话租约，分别维护查询上下文和派单状态。
2. 在 HTTP MCP 业务边界增加受控查询工具；报表适配器补齐不限派单状态的有界读取，派单查询绑定持久清单和当前权限。
3. 实现工单提供者、固定流程与审批人、详情及聚合总结；每条结果注明演示性质、来源和时间，不由模型补造流程事实。
4. 增加可恢复的查询结果卡片、筛选与分页展示、工单时间线和总结，调整助手名称及能力引导；原派单确认卡片继续使用原执行路径。
5. 准备独立用例和保留问法，执行协议、权限、数据库、HTTP MCP、前端、浏览器和真实模型验证；失败保留并回归相关完整流程。
6. 更新当前操作说明、MCP 契约和图表生成器及产物；归档实际结果与未完成项。

## 数据及安全约束

- 演示库固定为 `report_demo`。本方案优先复用当前会话 JSON 和业务表，以独立演示流程资源提供工单数据，不为演示流程新建数据库或清空现有数据。
- 用户已授权本轮创建和清理独立临时测试库；授权不包含清空或重建 `report_demo`。如实现确实需要破坏性结构变更，先完成具体重建方案再取得授权。
- 租户与操作者由服务器注入；报表、公司和派单归属每次复核。模型只能选择公开查询能力，不能提供 SQL、身份或权限。
- 查询结果仅在成功完成后保存为事实卡片；分页和恢复须重新校验当前授权。相同查询的统计不能以当前页或扫描截断冒充全集。
- 工单操作本轮只读。催办、审批、修改工单及真实 ERP/统一认证接入不属于已实现能力，明确说明接口边界。

## 验证矩阵

| 层次 | 需要证明的行为 |
| --- | --- |
| 协议与模型 | 查询/派单区分，字段与状态映射，相对日期，连续追问，复合条件，不支持操作澄清，不同表达保留集 |
| 业务与数据库 | 含已派单报表查询，完整统计，稳定排序分页，大整数和金额精度，租户/公司/报表隔离，派单归属，零查询写入 |
| 工单 | 固定环节与审批人一致，多状态详情，当前待办与已完成区别，来源标识，实际派单关联，缺失与越权同样拒绝 |
| 前端与恢复 | 查询卡片、详情、总结、翻页，刷新与重启恢复，迟到响应隔离，查询/派单切换后原选择不被覆盖 |
| 整体 | 现有派单、规则、确认、幂等、执行版本、调查和上下文回归；实际真实模型 HTTP MCP 与浏览器证据单独记录 |

有限测试只能证明已执行场景，不能宣称任意问法都无错误。最终交付需逐项检查本表及目标范围，真实外部系统、生产容量和灾备继续以独立验收为准。
