# 表结构与代码注释优化（2026-10-03）

本次为维护规范与可读性优化，业务链路仍以 `real,mcp`、`agent.semantic.mode=active`、真实模型接口和带认证的 HTTP MCP 业务服务为基线。账号行为问题按约定暂缓，真实外部认证系统后续接入；前端框架、组件库和依赖版本保持原有版本。

## 规范与实现

[AGENTS.md](../AGENTS.md) 新增数据库与代码注释规范：表和字段必须使用真正的 MySQL COMMENT；实体字段、业务 DTO、公共业务方法和关键内部逻辑说明业务含义、有效范围、权限、状态、版本、幂等、失败恢复与副作用。普通赋值及框架样板无需逐行解释，注释不得代替业务校验或宣称待接入能力已经完成。

新增 V21 Java 迁移及冻结注释清单，覆盖 **35 张表、398 个字段**。迁移从当前连接的 SHOW CREATE TABLE 提取字段完整定义，只替换 COMMENT，保留类型、精度、字符集、排序规则、默认值、可空性、生成列及索引。注释清单校验和参与 Flyway 验证；V1～V20 不回写。未知扩展字段及外部系统业务表不在修改范围内。

四张报表业务表在已有库存在时由 V21 补注释，新库在首次迁移完成后的初始化脚本中直接创建相同注释。此次数据库验证使用独立临时库，没有执行现有业务库的初始化或重置。正常部署启动时由负责数据库迁移的业务服务应用 V21；本文不表示当前运行库已经升级。

代码补充了生产类型职责、**227 个实体字段**、**46 个请求与表单字段**、**75 个 record 的组件说明**以及 **26 个前端逻辑模块**的职责说明，重点解释异步任务入队与认领、执行版本冻结、数据库条件更新、租约过期、未知结果核对、语义范围合并、权限复核、来源数据写入和刷新恢复。保留前期已完成的功能修复，本次注释整理不扩大账号或前端依赖升级范围。

## 防止再次遗漏

`node tools/check-comments.cjs` 检查生产类型 Javadoc、实体与请求表单字段、record 的 @param、前端模块职责和初始化注释一致性；同时校验生成的 [表结构字典](db/表结构字典.md)。检查已加入 CI 与 `tools/test-regression.ps1`。字典由 `node tools/generate-schema-dictionary.cjs` 生成，后续新增迁移时扩展生成来源，不改写已经执行的 V21 清单。

静态门禁检查覆盖与一致性；方法注释是否准确、复杂逻辑是否说明设计原因，仍由代码评审判断。数据库注释真实覆盖和结构保持由 MySQL 集成回归确认。
