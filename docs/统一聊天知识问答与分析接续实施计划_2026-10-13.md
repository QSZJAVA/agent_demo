# 统一聊天知识问答与分析接续实施计划

## 目标与范围

在现有聊天入口完成业务查询、知识解释、有限多步分析之间的正确路由，让“只分析刚才这些”严格使用已授权的原查询快照。保持派单的人工确认、业务权限、版本与租约保护。使用现有真实模型、原生 JSON Schema、`real,mcp` 与认证 HTTP MCP；不升级依赖，不接入真实 ERP/工单、外部认证或生产准入。

用户已授权实现、自测、逐库创建/写入/清理本仓库隔离夹具及提交推送，无需重复确认。保留 `report_demo`、执行前已有库、其他用户进程及全部 IAB 标签。

## 契约与执行边界

1. 扩展现有 `TaskPurpose → AssistantPlan → 独立复核 → 有界修正`，增加 `KNOWLEDGE`、`ANALYSIS` 路由，不另建关键词路由器。分析指令只选择单公司单报表、模式及可选服务器查询引用；外层将本轮完整原文绑定为分析问题，模型不能另改问题或提供任意 snapshotId、身份、执行工具。
2. `AnalysisContract.Request.mode` 必填：`KNOWLEDGE_ONLY` 只允许 KNOWLEDGE 且无快照；`SNAPSHOT_ONLY` 只允许 SNAPSHOT/GROUP/RANK/DRILLDOWN/KNOWLEDGE，必须绑定明确快照，禁止 QUERY/COMPARE；`CURRENT_DATA` 允许现有有限只读图，显式给定的快照可参与与当前数据比较。模式参与请求幂等哈希、配置、动态 Schema、全图验证、逐步执行及恢复验证。
3. 成功业务查询在 DialogueState 保存完整 snapshotId、查询引用及已有权限范围。只允许承接当前业务查询焦点中完整、同公司同报表、本人有权且未过期的快照；失效或歧义明确拒绝/澄清，不能静默查当前数据。
4. `AnalysisEngine` 已依赖 BusinessAssistantService；分析创建由 SemanticConversationService 外层协调，使用预检回调传给规划器，不反向注入 AnalysisService。草稿预检允许重入，但不能创建分析任务。

## 可靠提交与恢复

1. 新增 `chat_turn_receipt`，专门负责模型调用前的接收、稳定幂等及可信分析提交状态；既有 `semantic_turn` 继续保存处理后的语义审计。两者生命周期与职责清晰，不把异步 AgentMessage.id 当请求号。
2. HTTP 聊天要求客户端稳定 `Idempotency-Key`，服务端以租户/本人/key唯一绑定完整输入哈希。新会话与接收记录同事务；同键同载荷回放，同键异载荷409；首次接收才产生服务器 requestId。
3. 状态为 RECEIVED、PLANNING、READY、SUBMITTED、COMPLETED、INTERRUPTED/FAILED。模型前先保存 PLANNING 和有限截止时间；中断且无可信分析请求时不能重推模型，明确提示用户以新问题重做。
4. 复核通过后在原会话租约下保存 READY：完整可信 Request、权限/知识/执行配置指纹。随后在 `session.fenced` 短事务内按 `analysis-<requestId>` 创建/回放子任务，关联回执、保存状态及稳定事件键卡片。READY 恢复仅由显式核对触发，重核原指纹及快照，不重新解释原文。
5. `GET /api/agent/turns/{key}` 只读取当前授权回执；重复 POST `/api/agent/chat` 使用原 key/载荷显式恢复，以 SSE 返回原 conversation/requestId 和 replayed 标记。普通刷新不 POST。
6. `analysis_task` 卡片仅保存 requestId、runId、mode 和业务范围，答案通过 AnalysisService.get 实时核对权限与资料版本后读取。历史消息核验会话—轮次—任务关联，不信任缓存卡片；不可用时清空答案并中性展示。业务历史权限保护覆盖知识/分析范围。
7. 新接收记录纳入会话删除及到期治理；到期保留防重身份，清理可信请求正文，不能让过期 key 重建任务。

## 前端与交互

发送前按 userId/token 摘要保存完整载荷与 key，并回读确认。共享待核对存储的身份、摘要、TTL 与条件清理机制，各领域独立限制载荷，不能截短查询条件/排除项。首帧或尾帧丢失后 GET 找回原会话；显式“核对本次提交”才以原 key POST。未知结果不得被新请求覆盖。

任务卡片 GET 轮询展示状态、步骤、答案与依据，支持进入现有分析工作区；身份切换、离页、隐藏和迟到响应均有守卫。新模式贯穿独立分析页、深链、回填、待核对及明确切换，不兼容旧本地结构。查询编辑、澄清选项、预览、派单确认保持原约束。

## 验证和完成条件

- 模式、Schema和动作白名单；缺失/未知字段、越权、快照失效、知识版本/配置变化；原有多步图、明细恢复及金额精度回归。
- 接收同key同/异载荷、首次会话并发、首响应丢失、READY中断、创建后响应丢失、租约过期、删除墓碑、重复卡片、记录到期和权限撤销。
- 真模型知识/分析/查询/派单路由与代表性同义表达；核对实际模型阶段、HTTP MCP调用次数和确定性最终结果，禁止用解析成功代替业务完成。
- 新隔离库验证最新V1空库、表字段注释及目标结构；逐库记录创建与清理，旧库集合不减少。
- 前端逻辑、构建和真实浏览器知识问答、当前数据分析、原快照接续、刷新/丢响应核对及失权恢复。截图、DOM、原失败和最终结果分别归档；保留IAB。
- 执行注释/文档/基线/无旧兼容及 git diff 门禁，审阅实际证据与凭据扫描。完成后形成详细中文提交并推送，核对远端HEAD与工作区。
