# 知识检索准确性与试查实施计划

日期：2026-10-12（Asia/Shanghai）。实现基线为已推送的 P2 提交 `286a255`。用户授权继续优化、实现及自测；本轮不包含生产准入、真实工单、外部 ERP 或正式身份系统接入。

实施和自测记录见[本轮实现与验收](review/知识检索准确性与试查实现与验收_2026-10-12.md)，保留首次失败、接续修复、真实链路与浏览器恢复证据。

## 问题与交付目标

当前检索把英文词也交给子串匹配，`tax` 会命中 `syntax`；已发布词典的字段别名没有参与召回，同一长文档的多个片段可能挤占其他来源。管理员只能通过完整模型问答间接判断资料是否能被找到，缺少只读、可解释的试查入口。

本轮完成同一授权范围内的精确词界、有界字段别名扩展、来源均衡与检索试查。保留真实模型规划、引用验证和独立语义复核；检索排序和词典别名不能证明业务结论正确，也不能将两个指标自行视作等价。

## 实施范围

1. 规范化大小写、全半角和空白后，英文/数字/下划线标识按完整词界匹配；中文保留有界二/三字召回。长问题和候选数继续受限，不用无关默认资料补足结果。
2. 只使用当前租户、公司、报表下已经验证的词典 `field` 和 `aliases`。别名必须完整出现在原问题中，扩展不递归、不使用自由文本 `meaning`、枚举或公司别名推断同义关系；扩展词最多 64 个，达到预算时明确提示。
3. 来源契约显式保存原始来源标识，知识切片和引用再切片均保留同一标识。按相关度确定来源顺序，先给不同命中来源各一个片段，再按轮次补充，返回最多 12 个可完整引用的片段。
4. 返回实际命中词、直接/别名命中区别、扩展依据，以及搜索/命中/返回的来源数与片段数。明确候选截断和扩展截断，不把“没有召回”写成“所有制度都没有规定”。
5. 管理员知识页面增加“检索试查”，严格解码单一范围与问题表单，复用分析执行的检索、发布版本、生效日期与业务权限。它不调用模型、不读取业务行、不创建分析任务、不保存试查问题。返回前重查身份及依据指纹；页面切换范围、修改问题、刷新、发布/停用及销毁时丢弃旧结果与迟到响应。
6. 分析步骤和试查页面复用同一结果展示组件，展示来源原文、版本、范围、命中词和覆盖情况；内容按文本渲染。
7. 回答和独立复核使用相同的检索执行事实，明确区分未执行与执行后无命中；来源与片段计数分别命名，返回片段数取实际候选列表。知识资料的公司/报表是授权隔离边界，不按报表字段限制正文主题；不能凭报表名称提前断言制度不足或要求切到未核实的其他范围。
8. 独立复核同时核对结论与限制说明，拒绝时指出具体事实差异，最终判定与理由一致；保留有界修正和失败终态，不将矛盾的拒绝理由自动改成批准。
9. 检索计量成为独立的程序执行证据，回答需要复述计数时显式引用，仍经过原有严格数值和独立语义复核。它不占知识正文片段预算，不是业务明细，不证明制度结论，也不由程序自动补写模型说明或引用。

## 验证与证据

- 先保留英文误命中、长来源挤占的失败复现，再验证词界、大小写/全半角、中文、空命中、别名触发与不递归、扩展上限、来源均衡和稳定排序。
- 隔离库验证管理员和租户/公司/报表范围、未发布/未来/过期/停用资料、词典版本、严格 HTTP 表单、只读试查与原分析一致性；前端验证切换、迟到响应、失败与重试。
