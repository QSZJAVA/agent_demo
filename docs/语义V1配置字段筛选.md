# 语义 V1：配置驱动的字段筛选（2026-10-07）

当前链路使用 `real,mcp`、`agent.semantic.mode=active`、真实模型接口和带身份认证的 HTTP MCP 业务服务。模型为本机已配置的 `deepseek-v4.1-flash`，请求原生 JSON Schema，thinking 关闭。V1 是原 V4 完整功能的重新编号，应用包为 1.0.0；实际验证结果见 [本轮验收记录](review/V1重新编号与验收_2026-10-06.md)，历史结果保留原版本。

## 字段配置如何进入语义流程

报表目录通过 `FieldInfo` 声明字段名、类型和说明，并通过适配器返回 `FactRow.facts`。语义能力和持久字段快照共同使用该目录契约，支持单据、摘要、客户实体及配置字段筛选。

V1 从当前授权目录直接生成 `fieldsByReport`，给模型提供业务字段名、类型、说明以及各类型允许的操作，不提供物理表名、SQL 或全租户客户数据。新增已支持类型的业务字段通过目录配置及来源事实返回即可接入，不需要在解析器中添加该字段或客户的专用分支。

当前三张示例表的业务字段包括：

| 报表 | 配置中的主要字段 |
| --- | --- |
| 销售 | `orderNo` 订单号、`productName` 产品名称、`amount` 金额（元）、`saleDate` 销售日期、`companyCode` 公司；派生 `daysSinceSale`、`dispatched` |
| 应收 | `invoiceNo` 发票号、`customerName` 客户名称、`amount` 金额（元）、`dueDate` 到期日、`companyCode` 公司；客户实体字段及派生 `daysUntilDue`、`overdue`、`dispatched` |
| 费用 | `expenseNo` 报销单号、`expenseType` 费用类型、`amount` 金额（元）、`expenseDate` 日期、`companyCode` 公司；派生 `daysSinceExpense`、`dispatched` |

客户别名 JSON 数组用于实体关联，不作为普通标量比较字段；未配置字段、排序、条数限制和多步查询程序仍需说明限制或澄清。

## 受控条件协议

V1 包含 `FIELDS` 选择器和 `conditions`，只接受当前协议，不读取旧版 JSON。条件为最多四个 OR 组，每组最多八个 AND 条件，无递归脚本表达式。每个条件包含配置字段名、比较操作、字面量数组及本轮原文证据。

- 数值、整数和日期：EQ、NE、GT、GTE、LT、LTE、IN、NOT_IN、IS_NULL、NOT_NULL。
- 文本：EQ、NE、CONTAINS、STARTS_WITH、IN、NOT_IN、IS_NULL、NOT_NULL；文本比较按原文区分大小写，不自动猜测业务别名。
- 布尔：EQ、NE、IN、NOT_IN、IS_NULL、NOT_NULL，值为 `true` 或 `false`。

排除匹配项用 EXCLUDE，恢复匹配项用 RESTORE，只保留匹配项用 KEEP_ONLY。报表限定只影响该报表的记录，不替换整个查询范围；若另有明确的报表范围修改，必须有独立原文证据，字段条件本身不能充当范围修改证据。单据号仍可直接使用 DOCUMENT，不要求用户指定字段名。

整类取消或恢复勾选使用 `ALL` 选择器，操作为 EXCLUDE 或 RESTORE，数量为 ALL，实体及条件数组为空。它作用于当前候选或 `reportMentions` 指定的报表，不改变查询报表范围，也不使用虚构的恒真条件。

派单候选包含不同字段集合的报表时，每个 AND 条件组必须至少能在一张当前报表中完整求值；只在声明了该组全部字段的报表中执行，其他报表不匹配。未声明字段不能当成业务 NULL，未知字段或无法在同一报表成立的字段组合仍整体拒绝。这不改变普通业务查询的跨报表公共字段契约。

最近成功的记录选择保留其实体证据，失败草稿不能覆盖。明确、唯一承接该实体的追问可使用已确定的字段值，仍在当前授权快照上验证；本轮证据不得补写历史名称，不引入相似客户自动合并。公司代码可带中英文类别称谓，去掉称谓后继续按实际授权代码精确验证。

当前预览内最近定位的记录另提供 `REFERENCE` 引用：模型只看到随机引用键与公开字段，服务端保存键到预览及复合记录标识的绑定。引用操作的 `mentions` 使用已有键，`evidence` 仍来自本轮原文；未知键、预览变化、报表限定不符及单笔引用匹配多条均拒绝。引用最多保留 50 条、32KiB，超限明确标记不完整；预览刷新和手工选择变化清除旧引用。当前预览上的记录定位另在模型草稿阶段无副作用预检，最多使用两次草稿修正机会，正式执行仍重新验证权限、快照与选择。

引用还会与当前公开候选名称、单据及本项证据、整轮原文做冲突检查：本轮明确点名了其他候选且与引用对象不相交时拒绝，要求模型重新按原文定位。检查不会生成选择、替换引用键或按相似名称合并记录；纯指代仍依赖原有预览绑定与数量校验。

仅调整候选选择不授权顺带建单。包含记录修改的 PREPARE_DISPATCH 组合还须有本轮清单、待确认、派单等明确动作依据；缺少时拒绝草稿并由模型重新判断完整动作，正式处理也保留该校验，不按词语自动改写意图。

准备清单的模型上下文包含当前有效预览中已选记录的完整数量与有界字段事实，用于区分“描述已经留下的记录”和“再次修改选择”。该事实不构成建单或执行授权，仍需本轮明确准备请求及独立人工确认；经历普通业务查询后，旧派单选择不作为当前可用事实发送。

记录的报表限定可引用同一轮另一分句中出现的报表名；记录自身和字段条件仍须有连续原文证据。该规则等价于默认引用整轮 evidence，避免因局部证据片段不重复报表名而误拒绝；历史报表名、模型补造的名称仍不接受。

KEEP_ONLY 支持按字段、单据、客户、摘要及当前预览引用定位；它会排除匹配集合之外的全部记录，因此还要求连续原文中有“只保留/仅留/只选/only”等明确排他限定；普通“保留/选上”不构成此授权。校验只拒绝无依据的操作并交给有界模型修正，不根据词语自动生成意图。无法确定排他含义的其他表达会澄清，不猜测扩大排除集合。

明确单笔引用（如“那一笔”“一张发票”“one invoice”）不能使用 ALL。校验只拒绝扩大数量，不猜测具体记录；ONE 匹配多条时由实体解析澄清，用户需指定单据号后才能继续。

明确要求某报表“不动”时用 `reportConstraints.UNCHANGED`，与从查询范围排除的 EXCLUDED 分开。服务端校验该报表的公司和范围成员关系保持一致，拒绝同时覆盖它的记录操作；不限定报表的记录操作也不能绕过该保护。仅操作选择时复用有效预览，原预览失效则澄清，不能声称旧选择仍保持。

“其余报表不动”用 `UNCHANGED_OTHERS` 表达明确记录操作范围的补集，不把“其他报表”当作目录名称。它只允许查询范围不变、每个记录操作都有具名报表限定的请求；未限定记录操作或同时切换公司/报表范围会被拒绝。未应用的保持不变约束不会把已确定报表范围标成未知，未完成请求仍阻止省略建单。

`FieldSelection` 先对范围内各报表编译目录白名单、字段类型和操作，再在完整授权快照中求值。条件中的未知字段、非法操作、类型错误、缺失快照或目录类型变化均拒绝，整轮不留下部分排除结果。跨报表条件必须适用于指定报表的字段；专有字段应明确所属报表。

金额使用 `BigDecimal`，不会将大于误写为大于等于；日期使用 ISO 日期。模型参考当前上海日期解释相对日期，原文证据仍保留原说法。数值限制为最多 65 位有效数字、绝对 scale 不超过 30，覆盖 MySQL DECIMAL 的精度和小数范围，不截断或舍入来源值；整数还须满足 Java integer/long 范围。空值不满足普通比较，包括 NE、NOT_IN；判断空值必须显式使用 IS_NULL。

## 冻结事实与失败恢复

手动勾选通过 `PUT /api/agent/conversations/{id}/selection` 立即持久化，携带当前 `previewId`、修改前的 `expectedExclusions` 和目标 `excludedRecords`。服务端在对话租约内检查归属、有效预览、完整记录键和旧集合；另一页面已修改则返回冲突，相同目标的丢失响应重放保持幂等。保存期间界面暂停建单与新轮次，保存失败须重读权威选择，不能把未保存的本地状态当作已成功。刷新恢复使用同一选择接口的 GET；此操作不建单、不确认派单。

`FieldFact` 按授权目录捕获标量事实，值以规范字符串保存，避免 JSON 浮点数往返丢失精度。`dispatch_preview_item.fields_json` 与 `dispatch_plan_item.fields_json` 保存 `{name,type,value}` 数组；value 为 null 表示来源空值，数组为空表示候选未声明字段，不能从展示金额或旧来源补造。来源未返回配置字段时拒绝生成不完整快照。

选择基于预览时刻的字段快照，刷新页面不会重新读取来源。清单复制同一份事实，业务服务将提交字段与已确认清单逐项核对，拒绝篡改。实际写入时，`ConfirmedRecord` 在来源行锁内比较记录身份、公司、金额、日期、客户稳定 ID 和目录声明的全部标量字段；数字按精确数值比较。任何变化、缺字段或损坏快照都拒绝执行，要求重新查询并确认，包括跨日变化的派生字段。此时不重新调用模型解释原始条件。

查询只激活完整预览。任一行规则求值异常、来源返回重复记录或越界公司、分页不符合契约、扫描超过预算，整次查询明确失败；已写入的 BUILDING 部分明细会清除，旧预览和待确认清单不会因失败扫描而失效。管理员试算单独统计错误数，不能把试算结果当作正常业务预览。零匹配仍是合法完整结果。

默认每次扫描最多 100000 条、120 秒，每页最多 500 条，由 `agent.preview.max-scanned-rows` 和 `agent.preview.max-scan-seconds` 配置。扫描超限需缩小范围后重试。这限制资源成本，并未减少低命中率时 HTTP MCP 需要读取的数据量，也不是生产容量证明。

模型出站对明确密码、令牌、密钥样式输入直接拒绝；业务上下文与调查消息统一脱敏，不沿用展示层对机器字段的豁免。字段名标识的敏感值和 FieldFact 的 value 一并清理，工具调用配对 ID 保持有效。策略只覆盖已定义的字段和模式；客户商业秘密分级、允许出站字段、供应商保留策略仍需随真实数据接入确定。

新增 `unresolvedRequest` 表示上一轮请求整体未完成。它不会把已经确定的公司和报表一起标记为未知；失败不提交该轮修改，后续明确的新查询或记录操作可基于保留范围继续。仅说“剩下的派单”等无新限定请求仍被阻止。模型明确报告的公司、报表或记录歧义继续使用各自未解决标记，实际权限拒绝仍保留用户请求范围，不回退到另一家公司的成功结果。

普通业务查询保留旧预览及选择，但形成独立业务边界；返回派单时仍需明确取得新候选。此时若明确换到不同报表，已经移出报表范围的旧排除键不再参与新选择。当前报表内失效记录及连续派单流程的普通范围切换继续执行原有恢复校验，不能用范围变更跳过用户选择保护。

CLARIFY 意图中未执行的候选范围修改只作证据保存，不因其存在而设置公司或报表歧义。格式或证据校验失败时，最多两次草稿修正均收到当前请求、脱敏后的被拒绝草稿与汇总诊断；不得把该草稿当作新的用户指令。修正仍失败则整轮澄清，不执行部分意图。没有按客户、字段名称或具体问句增加程序分支。

## 基线和验证边界

当前 Demo 库固定为 `report_demo`，最新初始化为 38 张表、456 个字段。结构变化时仅在用户明确授权后重建同名库，不另建带日期或版本的数据库，不做旧快照转换或 Flyway 校验和修复。使用当前基线启动：

```powershell
.\tools\start-mcp.ps1 -Build -Frontend -Database report_demo -NativeSchema true
```

字段选择真实回放由 `tools/test-semantic-fields.ps1` 在该专用基线上执行，账号通过已忽略且限制访问的本机配置提供。原始问法、边界、日期、文本、AND/OR、布尔零匹配及失败恢复均保存在测试中，不进入提示词样例。脚本比较排除集合、预览标识、状态和是否意外建单，不以回答措辞代替业务断言。

程序回归、独立空库检查、真实模型加 HTTP MCP 回放、浏览器恢复分别取证。此前 V3 的模型遗漏条件、误改范围问题及其历史失败保留；本轮有限场景通过不能证明任意表达或生产部署通过。外部 ERP、正式外部认证系统、容量和灾备验收仍待实际接入与验证。
