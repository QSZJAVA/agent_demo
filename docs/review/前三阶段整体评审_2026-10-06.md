## 确认的 BUG

### S1 / P2：合法的小响应预算使分页工具拒绝本来放得下的结果

位置：[InvestigationTools.java](../../backend/src/main/java/com/example/report/investigation/InvestigationTools.java)，第 167～168 行；[InvestigationProperties.java](../../backend/src/main/java/com/example/report/investigation/InvestigationProperties.java)，第 50 行。

配置校验允许 `max-tool-result-utf8-bytes=512`，但 `page()` 判断内容体积时固定扣除 512 字节。此时内容预算变成 0，连空结果的 JSON 都无法通过，随后抛出“单条证据过大，请查看原始追溯”。该方法同时用于 `plan_items` 与 `execution_events`。

本轮调用实际工具实现进行离线复现：

| 输入 | 正常工具封装后的完整响应 | 上限设为 512 字节后的结果 |
| --- | --- | --- |
| 单个 UNKNOWN 条目，size=1 | 312 UTF-8 字节 | 拒绝，称单条证据过大 |
| 单个条目无执行事件，size=1 | 176 UTF-8 字节 | 同样拒绝 |

上述配置通过 `InvestigationProperties.validate()`。复现使用合成事实与受控仓储，不调用真实模型、MCP 或数据库。问题位于原有分页预算逻辑，不是第三阶段压缩器新增的错误；默认 8192 字节不会触发这个特定反例。

影响：用户按已允许的范围缩小工具响应预算后，模型连最小状态页或空事件页都读不到，减小 size 也无效。重复纠正会消耗工具预算，最终只能提供证据不足结果或失败，且报错原因误导使用者。

建议按实际外层封装计算可用内容预算，并校验最终响应体积；或者明确提高配置下限并在启动时拒绝不可用值。补充 512 字节、略高于下限以及默认预算的条目和空事件分页回归。已有小预算测试只覆盖远端核对，未覆盖这两个分页工具。

## 三阶段设计合理性

| 阶段 | 当前实现 | 评审判断 |
| --- | --- | --- |
| 第一阶段：自主工具调用 | 应用控制循环；静态只读工具、运行内引用、权限与预算检查；快照、证据、取消和任务恢复 | 合理。模型负责选择查询，程序保留授权与执行控制权，没有把调查建议变为派单操作 |
| 第二阶段：评估与调试 | 独立语料和评分器、开始/完成轨迹、配置与编译产物指纹、检查点、续跑父锁与后继登记、共享对比控制变量 | 合理。已避免用生产校验器直接替代任务评分；失败与未知调用结果保留，续跑不会按成功覆盖失败 |
| 第三阶段：上下文工程 | 确定性证据笔记，保留系统规则、原问题与最近完整工具轮次；六个只读工具包含运行内证据回读 | 合理。笔记来自已保存证据，避免把模型摘要变成事实；压缩只在轮次边界执行，关键状态与多次远端观测得以保留 |

上下文是单次运行内存，不是跨会话长期记忆，也不是进程中断后的续推理。原问题和系统规则不被压缩覆盖；新运行不继承上一运行的证据。来源改变、撤权、取消和失租仍经过原有检查，证据回读不能跨运行取得材料。

选择受控报告正文降低了错误成功、修复或重发声明的风险，但也限制了能力：当前更接近“有证据的状态归类与受限建议”，不能据此宣称实现开放式根因分析。这个范围适合当前 Demo，不应通过恢复任意自由文本输出来扩大承诺。

结构化笔记阈值是软阈值，实际模型请求还有独立上限。保留必要事实后仍超限时失败是明确设计，不应为了压缩率丢掉权限约束或状态证据。后续若要评估上下文工程效果，应比较同题在事实正确性、输入字节、调用数和时延上的变化，而不是只看消息变短。

## 第三阶段的验收缺口

当前 [上下文工程设计与验收](../上下文工程设计与验收_2026-10-06.md) 明确说明移除 RAG 后没有重新调用真实模型。历史 [上下文工程与 RAG 自评](上下文工程与RAG自评_2026-10-06.md) 的 18/18 也明确记录没有触发默认上下文压缩。因此这些结果均不能证明当前真实模型在压缩后正确理解笔记并按需回读。

现有上下文测试包含强制降低阈值的实际 Agent 循环、UNKNOWN 与 SUCCESS 两次观测同时保留、最近消息配对、运行隔离和回读缺失标记。这些证明程序行为，但不证明真实模型自主使用压缩后的上下文。

建议增加当前版本的长轨迹验收：

- 使用有业务意义的多页长事件或规则证据，实际触发 `CONTEXT_COMPACT`，记录前后字节数及原调用 ID 配对。
- 覆盖压缩前后关键状态不能丢失、被省略信息确实需要回读的场景，并观察真实模型是否调用 `evidence_read`。
- 分别记录真实模型与合成事实、真实 HTTP MCP、数据库状态机、浏览器证据，不把它们合并成一个泛化通过率。
- 保持相同题目、事实、模型与预算做对比；压缩开销增加、没有变小或无法满足输入上限也如实记录。

这属于第三阶段补充验收建议，没有在本轮虚构新的真实模型结果。
