## 修复与反例

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| N1 批量核对丢失事实 | 查询前校验整批引用和剩余资格；每条核对结果立即保存，未实际开始查询的条目不消耗次数 | SUCCESS、FAILED、NOT_FOUND 条目位于批次末尾时，前方新条目没有远端调用或计数副作用；纠正参数后取得成功证据。UNKNOWN 两次、重复引用及越界引用也整批拒绝 |
| N2 同一父归档重复续跑 | 读取父清单/检查点前加独占锁，子批次关闭才释放；首次调用前原子登记唯一后继 `continuation.json` | 当前 JVM 与另一 JVM 的第二位续跑者均被拒绝；第一位关闭后仍不能再次从父归档分叉。后继可继续尚未开始题次，原失败保留；后继有未完成 STARTED 时父、子路径均不能绕过保护 |
| N3 请求路径遗漏 | Java 续跑与 Node 对比共用控制变量 JSON，纳入 `completionsPath`、业务时区、价格及执行节奏 | 实际 CLI 对路径/时区变化、双方缺字段或空字段均返回不可比；空批次、重复题次、事实不匹配和阻断批次也不可比 |

相邻边界同时补齐：

- 后一条预算耗尽时，前一条成功证据仍持久化，并在无工具的报告阶段交给模型；有实际 Agent 循环回归验证这一点。
- 小响应预算下只裁剪补充文本，保留状态与条目身份；整批响应过大时返回证据回执，避免在查询之后再以可恢复参数错误丢弃事实。5 条结果、512 字节响应上限的反例通过。
- 父归档拒绝配置不一致时释放锁且不登记后继；价格与费用以精确十进制读取，避免相同高精度价格被误判为配置改变。
- 归档关闭后禁止继续改写最终清单；来源变化、撤权、取消、认领令牌及数据库证据写入保护继续保留。

本次未修改数据库结构、Demo 账号生命周期实现或依赖版本。续跑检查点使用 `journalVersion=2`，旧归档保留原始事实，不转换或补造检查点。操作说明已同步更新。
