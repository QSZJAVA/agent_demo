## 业务问题与修复规则

原检查点将“一千块以上”错误处理为严格大于一千。首轮复验进一步发现：规划器给出正确条件后，独立复核可能错误改变等号，或从更早对话恢复已经撤销的费用类型限制。

当前规则如下：

| 业务要求 | 应有行为 |
| --- | --- |
| 以上、至少、不少于、不低于 | 包含恰好等于阈值；使用大于等于。 |
| 以下、至多、不超过、不高于 | 包含恰好等于阈值；使用小于等于。 |
| 超过、大于；少于、小于 | 排除恰好等于阈值。 |
| 明确“不含本数” | 只调整相应端点的等号，不对整个区间取反。 |
| 一个区间的上下限 | 同时满足两个条件，分别核对两个端点。 |
| 取消选择或恢复候选 | 数值条件描述被操作集合；排除、恢复不再次反转比较符。 |
| 修改阈值、比较符或一个端点 | 保留其余有效条件；不误记为整个字段被撤销。 |
| 调整上限时已有下限，或反向调整 | 分别核对两个旧端点。每个被替换或删除的旧条件都须有本轮依据，不能仅因金额字段仍在就放行；修改上限不授权删除下限。 |
| 撤销整个字段后继续修改其他条件 | 不从较早对话自动恢复已撤销字段。 |
| 复核结构或证据错误 | 先修正复核自身，合法期望才可用于比较草稿；不据错误复核改坏正确草稿。 |
| 查询失败后的明确补充 | 按当前请求及可靠上下文重新形成完整查询；失败请求不作为成功查询继承。 |
| 先查看候选、或口语“准备看一下” | 只展示可派候选，不额外创建待确认清单。 |
| 先准备但不提交执行 | 可以生成待确认清单；禁止提交是独立约束，不误认为禁止准备。执行仍须用户在页面确认。 |
| 调整部分报表、保留其余 | 区分报表范围变化与记录选择；不把“其余”当成报表名称，不补写本轮没有的报表全称。 |
| 使用简称或英文报表别名 | 按本轮原词绑定授权目录；不能翻译成另一段原文，也不能删除限定以通过校验。 |
| “天津那家的恢复”等自然指代 | 已有唯一、完整且有效的定位引用可使用；字面别名匹配失败不等于可靠引用不存在，多义时仍澄清。 |
| 只读查询打断旧派单候选 | 直接要求准备时说明需先重新核对候选；用户明确要求核对后才能恢复准备，不自动确认或换成另一动作。 |
| 已经完成的排除后准备清单 | 使用当前保存的选择，不重放历史排除，也不把历史条件填入本轮条件证据。 |
| 明确从头查询与继续查询 | 首次草稿前独立判断“是否承接”；从头重建不继承旧排除，续查保留仍有效条件。 |
| 从头查询同时说“不再保留旧限制” | 直接使用完整新条件，不填写只属于续查的旧字段撤销声明，也不为保留该声明改成续查。 |
| 询问是否支持审批 | 解释能力与只读边界；询问能力不构成执行审批的授权。 |
| 选择在规划或复核阶段失败后要求建单 | 不能把失败前的旧选择当作调整成功后的集合；先重新展示核对，或按本轮明确的完整选择重新预检。 |
| 完整指定报表范围 | 一次替换为完整集合；全部授权范围不等于空集合，不能先选全部再追加来表示“只要某张”。 |
| 明确最终清单条数 | 独立目标和详细复核须保持一致，并与完整预检实数核对；漏填总数不能绕过校验。局部恢复条数不等于最终总数。 |

复核须逐条说明字段条件来自本轮要求、当前有效查询或实际已展示对象。对同范围续查，还须逐项说明不再原样保留的旧条件及其变更作用域；只修改一个端点的依据不能扩大为另一个端点或整个字段的撤销。当前查询中已经不存在的条件不能作为“继承条件”。对原文中阈值和关系明确且唯一的比较，程序另核对方向与等号；校验只拒绝冲突，不生成意图或自动修改计划。其余语境仍由真实模型复核。

未知 JSON 字段的反馈明确指出需要删除的字段和允许的对象结构；原文引用错误明确指出字段和值。可解析草稿的契约错误与独立语义差异在首次修正时一起反馈，独立复核本身的前提、原文和条件错误也一并反馈，仍遵守每轮最多三次规划、三次独立判断的预算。复核先给完整计划，再为其中实际存在的条件填写证据。权限、执行版本和业务服务故障仍直接返回，不通过条件修正更换目标。

SELECT order_no, product_name, amount, dispatch_status
FROM report_sales
WHERE tenant_id = 'T001' AND company_code = 'A' AND amount >= 96000
ORDER BY id;

SELECT expense_no, expense_type, amount
FROM report_expense
WHERE tenant_id = 'T001' AND company_code = 'A'
  AND amount >= 680 AND amount <= 3200
ORDER BY id;

FROM dispatch_plan
WHERE user_id = 'readerA'
