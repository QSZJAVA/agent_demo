用户已明确授权本轮创建并清理独立临时测试库，外部 ERP 与统一认证另行安排。演示库保持 `report_demo`，未清空、重建、改名或重置来源派单状态。账号生命周期及前端依赖升级仍按仓库约定暂缓。

## 实施结果

| 问题 | 本轮仓库内处理 | 验证边界 |
| --- | --- | --- |
| R1 确认事实变化 | 业务服务先核对持久清单的金额、日期、身份、字段快照，再在来源行锁内比较全部确认标量；不同金额精度表示按数值比较，字段缺失或变化拒绝 | HTTP MCP 覆盖金额、日期、产品字段变化、重复提交、伪造字段与顶层金额/日期；类型矩阵包含六类字段及空值 |
| R2 不完整查询被当作成功 | 普通预览和执行资格复核遇到规则错误立即失败；管理员试算单独统计错误；分批查询失败清理 BUILDING，不替换旧预览或使旧待确认清单失效 | 规则异常、非布尔输出、正常空值判断、普通与写满 500 条后的分批失败均回归 |
| R3 跨租户后台处理 | 派单与调查认领、过期恢复、调查清理和预览孤儿回收绑定本部署租户 | 独立 MySQL 回归验证 T001 不处理 T002 的排队、失租、过期数据；不等于多租户 SaaS 公平性与容量验收 |
| R4 模型出站 | 明确凭据样式输入阻断；结构化敏感键、FieldFact 值、自由文本、调查工具消息统一脱敏；机器字段不再获得模型出站豁免 | 合成凭据、多种键名、实际本机 HTTP 请求及工具配对验证；不宣称覆盖任意商业秘密或供应商数据治理 |
| R5 扫描成本 | 默认总扫描上限 100000 条、120 秒，每页最多 500 条；拒绝重复记录、重复游标、空标识、越界公司、超限与中断 | 合成 20000 条、41 页、20 命中的低命中率扫描；另测预算与异常来源。不是外部 ERP、并发或生产容量验收 |
| R6 门禁和说明 | CI 增加基线、兼容清理、字典检查；更新当前说明与八页流程图生成器及所有产物，修正陈旧注释 | 本机运行门禁与构建；未宣称远端 CI、镜像发布或生产部署通过 |

执行事实变化后必须重新查询确认，不能依赖旧清单重试绕过保护。派生日期字段跨日改变也会触发此契约。业务结果仍以当前规则、权限、来源状态、稳定请求号和执行版本保护为基础。

## 整体回归中继续发现和修复的问题

1. CLARIFY 中未执行的候选范围曾污染已确定的公司/报表，导致后续明确单据操作仍被阻止。现只由明确实体歧义设置相应标记，整体未完成继续阻止省略建单。
2. 模型结构修正此前只收到错误码，没有被拒绝草稿；同时存在字段证据改写和无依据报表范围修改时，一次修正难以定位。现提供脱敏草稿与汇总诊断，仍只有一次修正预算，不能执行部分意图。这是通用校验反馈，不增加客户、字段名或具体问句分支。
3. 顶层金额、日期也必须与持久清单绑定，即使某个目录没有将它们重复声明为字段列表，也不能仅相信提交负载。
4. 跨分句的记录操作可引用同一轮前文中的报表名，与默认引用完整原文证据一致；仍禁止引用历史或补造报表。避免只因局部记录证据没有重复报表名而误拒绝。
5. 后续回放实际发现“保留指定记录”被误解释为 KEEP_ONLY，导致多排除记录。现对这种排除其余全部记录的操作增加明确排他限定校验；普通“保留/选上”不授权排除其他记录。检查只拒绝无依据操作，不按词语生成意图，不绕过模型。
6. “另一报表不动”原来没有对应的协议角色，模型将其误填为 EXCLUDED 并被范围校验拒绝。补充 UNCHANGED 及服务端成员关系、记录操作冲突和有效预览校验；该能力适用于任意授权报表，不包含专有报表名称判断。
7. 客户保留集进一步暴露“其他报表”被当作目录名，及保持不变约束失败污染既有范围。增加相对集合角色 UNCHANGED_OTHERS：范围必须固定，全部记录操作须限定具名报表，由集合边界证明其余不变。未应用的保持约束只标记请求未完成，不改写已确定范围。
8. 复验发现模型把明确“那一笔”标为 ALL，错误排除同客户两条记录。补充单笔引用的数量校验：只拒绝扩大数量，不生成意图、不猜测具体记录；ONE 匹配多条由实体解析澄清。后续明确单据操作从未污染的选择继续。
9. 浏览器端复验还发现手动取消勾选没有持久化：清单是八条，刷新后的预览却恢复全选。新增带旧集合比较的选择保存接口，复用会话租约和有效预览保护；前端保存期间禁用后续操作，失败要求重读，迟到响应不覆盖其他会话。保留[修复前界面](production-fixes-2026-10-06/manual-selection-before.png)，新增 MySQL 并发/重放/权限与前端恢复回归。

真实模型预先固定两组 HTTP 用例：既有六场景十四步；新增九场景二十步，覆盖不同报表、数值写法、日期边界、文本、空值、布尔、AND/OR、跨报表累计、限定恢复、不支持条件和恢复。每步核对排除集合、预览 ID、阶段及意外建单，不以回答文案代替业务断言；澄清与业务成功单独计数。脚本维持普通账号限流，串行间隔至少三秒，不降低服务保护。

## 仍需外部证据的事项

本轮没有接入真实 ERP、正式统一认证，也没有完成生产并发、P95/P99、RPO/RTO、灾备、TLS/最小权限部署、供应商数据保留或远端发布验收。扫描预算、事务测试和有限真实模型回放不代表上述能力完成。Demo 账号问题和前端依赖版本保持既定范围。

有限语料通过不能保证所有客户、所有自然语言都成功；模型不可靠时必须继续安全澄清。正式试点应先约定业务成功率、错误范围率、时延与成本门槛，再在真实目录和接口下持续回放，不能靠删掉失败样本或重复尝试直到碰巧通过来报告质量。
