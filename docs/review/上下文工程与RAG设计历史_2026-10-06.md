## 第三阶段：证据驱动的上下文工程

`InvestigationContext` 在完整工具调用轮次之间检查逻辑消息 UTF-8 体积。默认超过 24576 字节时尝试整理，仅在新消息更小时替换原历史。保留系统约束、原始问题、最近完整的一组工具调用及对应结果，避免出现缺少配对的工具消息。

程序从当前运行已落库的证据生成 `PROGRAM_EVIDENCE_NOTES`：

- 绑定执行版本、证据 E 编号、条目范围、来源类型和截断标识。
- 保留所有已获得的条目状态和远端核对结果，包括先 UNKNOWN 后 SUCCESS 的两次观测。
- 保留缺失、完整性、分页游标、当前核对次数、检索状态及剩余工具预算。
- 省略旧规则及事件的长说明，需要时用 `investigation_evidence_read` 读取原有证据；省略不代表缺失。

笔记不保存模型内部思考，也不允许模型自行更新事实。`CONTEXT_COMPACT` 控制步骤记录整理前后体积和笔记，每次模型步骤记录输入体积与上下文策略版本。报告阶段同样使用确定性事实投影，不继续携带完整聊天历史。

记忆仅限当前调查认领轮次，不跨运行或账号复用。现有任务取消、超时、失租和进程中断策略保持有效；页面刷新只读已有持久化结果，不能因此再次调用模型。进程中断后的原任务按原设计结束为中断，重新调查由用户显式发起；本阶段不宣称已实现第五阶段的跨进程检查点续推理。

上下文目标阈值不是强制截断。若系统约束、必要状态和最近完整工具结果仍超过实际请求上限，返回明确预算失败，不删除约束或伪造完整报告。传输层继续独立检查包括工具定义和 Schema 的实际 HTTP 请求体积。

## 第四阶段：权限过滤、检索与证据回答

### 受控发布与分块

当前知识库为 `backend/src/main/resources/investigation/knowledge.json`，随代码评审和应用发布生效。它不是任意文件读取器，不抓取用户提供的 URL。每份文档有稳定编号、正整数版本、标题、租户、公司、报表、所需权限、生效与失效 UTC 时刻，以及按空行分段的原文。每段最多 600 字符，超限拒绝发布，维护者应按语义拆分。

`PUBLIC` 只允许不含租户数据的通用操作说明，公司与报表集合必须为空，权限类别为 `GENERAL`。租户材料必须明确公司集合、报表集合及所需权限，不能用空集合冒充公开材料。当前内置两份通用说明：结果未知与请求核对、复核跳过与规则快照核查。内置说明有效期为 2026-10-06 起至 2027-10-06 的配置时点，具体以文件中 UTC 时间为准。发布时拒绝可识别的敏感文本；维护者仍须审查材料内容，不将其视为通用秘密检测器。

### 先授权，再召回和重排

模型通过 `investigation_knowledge_search` 提供一个当前条目引用和 2～160 字符的查询。租户、身份、公司和报表范围由程序取得，模型不能传入身份或任意文件路径。

程序先重取当前用户授权，过滤不同租户、范围不符、权限不足、尚未生效和已失效材料。管理员也不跨越租户或数据范围。仅在可读候选中以中文双字词项和英文完整词召回，按词项覆盖及标题加权重排，稳定排序后返回最多三段。

这是词法 RAG 实现，没有新增向量数据库、Embedding 或外部重排模型。评分是排序值，不是语义置信度；同义改写可能漏检，应通过独立检索题集观察其边界。无词项交集返回 `NO_EVIDENCE`，不自动填入其他材料。

每个条目最多保存三段文档证据，相同条目与块编号去重，为报告阶段预留空间。片段包含文档编号、版本、块编号、原文、内容 SHA-256 和有效期；按 `DOCUMENT_CHUNK` 写入现有证据表。原文不截成半句话，引用编号必须落库后才能返回。

### 生成与校验

模型根据已检索片段选择处理参考，报告的 `guidance` 与业务状态 `findings` 分开：

| 字段 | 含义 |
| --- | --- |
| `itemRef` | 本轮目标条目 |
| `status=SUPPORTED` | 已检索到材料，提供 1～3 条完整原文引用 |
| `status=NO_EVIDENCE` | 已检索但无可用文档，引用为空 |
| `status=NOT_REQUESTED` | 本次未请求文档检索，引用为空 |
| `citations` | 模型只提交 `evidenceId` 与逐字 `quote`，程序补标题、版本和来源元数据 |

没有检索时可不提供 `guidance`；一旦检索，所有已检索条目都必须出现。引用必须属于当前运行、同一条目、未截断且当前仍有效的发布版本。伪造 E 编号、改写引文、跨条目引用、过期引用整份拒绝。文档 E 编号不能放入业务事实的 `findings.evidenceIds`，不会因“说明里提到成功”而把 UNKNOWN 判成成功。

本阶段采用证据摘录式回答，引用原段落并展示其适用背景，不开放模型自由编写制度事实。它验证引用忠实性，不等同于开放式因果解释或任意文档问答能力。文档、工具文本和笔记均标为数据；模型不能据此改变系统约束或增加写入工具。

前端以转义文本展示操作说明与引用，点击已有证据按钮查看来源，不执行片段中的 HTML、链接或命令。每次模型请求、报告返回以及 HTTP 报告/步骤/证据读取前重新检查文档权限和有效期。文档失效或撤权后阻断含其正文的旧结果读取，提示重新调查；已有证据仍按原保留策略保存供内部核查。取消仍复核任务归属及清单权限，但不因文档到期而禁止停止，取消响应不返回报告正文。

## 配置、评估与练习

新增配置 `agent.investigation.context-target-utf8-bytes`，默认 24576。模型运行配置记录上下文策略版本、检索器版本、知识库哈希和该预算。评估续跑必须保持这些配置一致；更换知识库会阻断直接质量对比，防止把资料变化误认为提示词改善。

检索与引用测试：

```powershell
.\backend\mvnw.cmd -f backend/pom.xml '-Dtest=InvestigationKnowledgeTest,InvestigationContextTest' test
```

完整回归沿用 `tools/test-regression.ps1`，涉及数据库的测试使用仓库专用新建临时库。真实模型任务评估沿用 `tools/test-investigation-live.ps1`，仅从已忽略的本机配置读取端点与凭据，不将凭据写入归档。模型未配置、鉴权失败或端点不可用时保留失败，修正真实链路配置后再显式运行。

建议练习：在有权查看的异常清单中输入“分析异常，并引用操作说明解释下一步核对流程”，观察 `knowledge_search`、引用版本和业务证据的区别；随后询问知识库没有的制度，确认无证据；在专用测试中降低上下文目标阈值、增加日志，核查压缩步骤及最终状态是否一致。修改材料版本、有效期或访问范围后必须重新发布并重跑检索与引用测试。
