# 整体评审与优化计划

日期：2026-10-11（Asia/Shanghai）。评审起点：`7922930`。本计划依据当前源码、现有测试与现场复现编写；此前验收仍保留其原日期与证据范围。实施与最终自测结果另行归档，不在计划中提前宣称通过。

## 项目判断

项目已形成报表查询、统一任务语义规划与独立复核、待确认派单、持久执行、异常调查和运营治理的完整 Demo。现有版本保护、稳定请求号、服务认证和失败核对有较多程序与历史真实链路证据。下一步的主要收益来自补齐共同的数据与状态契约，以及让用户能够找到、理解并恢复已提交的工作。

当前运行基线仍是 `real,mcp`、`agent.semantic.mode=active`、真实模型接口及认证 HTTP MCP。模型配置沿用已验证的 `deepseek-v4.1-flash`、原生 JSON Schema、thinking 关闭；本轮将重新记录实际执行范围。正式外部认证、真实 ERP／工单、生产容量和灾备仍待接入或验收。

## 本轮直接实施

| 优先级 | 发现与根因 | 实施范围 | 验收要求 |
| --- | --- | --- | --- |
| P1 | 卡片状态入口只验证归属，终态清单可在业务权限撤销后继续返回计数和状态 | 在卡片服务边界统一复核当前租户、公司、报表及会话可见性 | 权限撤销后所有卡片读取入口一致拒绝；合法用户仍可恢复终态 |
| P1 | 留存清理没有覆盖后来新增的字段和客户快照 | 统一清理已满足保留期的展示事实，保留防重身份、状态、请求号和仍需核对的证据 | 终态、失败、UNKNOWN、执行中、跨租户、重复清理的真实数据库回归 |
| P1 | 金额在 JSON、无类型快照、浏览器 Number 和合计中损失精度；空值显示为零 | 金额使用精确十进制字符串契约；前端统一精确格式化和求和，覆盖报表、预览、清单与历史 | DECIMAL 合法大额、小数、负数、空值、分页和历史回读一致 |
| P1 | 目录历史晚响应可展示 A 的历史却向 B 提交回滚 | 历史弹窗、显示版本与提交目标绑定同一请求代次和对象快照 | 乱序、切换、关闭和提交前失效均不能误回滚 |
| P1 | 运维指标只按租户聚合，未完整落实现有业务数据范围 | 对有归属的指标按当前授权过滤；无法准确归属的全租户指标明确说明访问条件 | 受限管理员不获得越权统计，空数据与无权查看可区分 |
| P1 | HTTP MCP 执行版本按 Number.longValue 转换，小数存在截断风险 | 为整数参数建立精确类型、范围与无损转换校验 | 小数、溢出、错误类型被拒绝，合法边界与确认版本保护仍有效 |
| P1 | 同步失败重试的缺省执行版本未绑定读取快照，并发下可能认领较新的轮次 | 缺省版本也使用读取时的执行版本进行条件认领 | 同一快照的并发重试仅一方认领，尝试计数和原请求号保持一致 |
| P2 | 规则字段和语法校验缺少编辑版本保护 | 字段、校验和试算绑定当前编辑会话与输入版本 | 切换报表／规则、修改表达式、关闭／销毁后旧响应不再生效 |
| P2 | 报表请求失败最终呈现为零条数据 | 共享分页状态保存错误并提供明确重试入口 | 真实空集合、加载失败、重试成功和请求乱序可区分 |
| P2 | 本机回归与 CI 的工具测试入口不一致 | 将现有语义比较器及调查评估比较器测试纳入 CI | 本机工具回归通过，工作流使用相同测试；不冒称远端 CI 已运行 |
| 功能增强 | 用户离开页面或丢失浏览器状态后，难以发现已经提交的派单任务 | 新增“我的任务”：本人任务游标分页、状态筛选、只读刷新、关联清单与追溯 | 当前权限过滤、稳定翻页、换筛选重置、刷新恢复、无任务及结果过期；读取不得产生新执行请求 |

不为历史数据增加兼容转换。数据库操作已获用户本次明确授权：仅在已核实的本仓库专用范围内执行；日常演示库仍固定为 `report_demo`，测试使用现有隔离夹具并核查其准确目标和清理结果。当前计划不需要为了绕过结构另建演示库。

## 自测与证据

1. 为实际业务缺陷补充有行为意义的回归，覆盖原失败、同类边界、并发与恢复；前端交互先做确定性逻辑测试。
2. 串行执行聚合 Java、数据库／状态机／HTTP MCP 程序回归；执行前端逻辑测试和生产构建，以及基线、注释、文档与工具门禁。
3. 使用真实浏览器验证新增任务入口和受影响页面，并通过真实模型、认证 HTTP MCP 验证查询、准备、确认边界及读取恢复。程序替身结果、真实模型结果、浏览器结果分别统计。
4. 保存实际失败与后续复验，不删除失败语料或改写评分以提高通过率；数据库核对读取任务不增加执行次数。
