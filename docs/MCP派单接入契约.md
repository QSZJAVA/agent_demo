# 后续业务派单的 MCP 接入约定

按 2026-09-29 的业务确认，真实派单等外部业务能力后续通过 MCP 接入。目前没有提供真实 MCP 服务地址、工具定义和认证方式，现有系统仍使用演示网关。

接入位置为 `DispatchGateway` 的实现。自然语言模型只生成结构化意图；服务端完成权限、范围、预览、确认、规则版本和执行权校验后，才由 MCP 网关适配器调用业务工具。模型不直接获得可绕过确认的派单工具。

## 待双方确定的工具契约

以下为建议语义，不代表已经存在的工具名称：

| 能力 | 输入要点 | 输出要点 |
| --- | --- | --- |
| 提交单条派单 | 可信租户和操作者、稳定记录标识、报表标识、公司、规则版本、幂等请求号 | 成功、明确未执行失败、结果未知；机器可读错误码和请求号 |
| 查询请求结果 | 相同租户和幂等请求号 | 成功、明确失败、确定未接收、暂时未知；必要时返回业务流水号 |

- `externalRequestId` 在超时、重试和进程重启后保持不变，MCP 服务需要持久去重。同一请求号不同负载应拒绝。
- MCP 服务的认证身份和允许的租户/公司必须与本地可信权限映射绑定，不能相信模型或浏览器提交的租户值。
- 业务系统在实际写入时原子校验记录归属、待派单状态和约定的业务前置条件，不能只依赖几秒前的查询结果。
- MCP 传输成功不等于业务派单成功。工具异常、超时、连接中断或格式不符合约定均进入结果未知，不能自动重发。
- 只有结果查询确认最终失败且契约允许重试时，现有 `retryFailed` 才可调用同一请求号；已成功项不再提交。
- 请求和响应日志需要脱敏；访问密钥从部署环境或密钥服务获取，不进入模型提示、源码、对话卡片或审计明文。

## 接入前需要提供

MCP 服务地址与传输方式、工具 schema、认证方案、测试租户/数据、业务错误码、结果查询一致性约定、超时和重试边界。确认这些信息后再选择 MCP 客户端并实现网关，避免绑定未经确认的私有协议。

## 必须通过的验收

重复确认仅产生一次派单；超时后成功可被查回；应用与 MCP 服务重启后幂等仍有效；权限撤销和版本变化阻止后续提交；部分成功仅重试明确失败项；结果未知先核对；全流程保留请求号和追溯证据。
