# RAG 语义检索与分析恢复实施计划

日期：2026-10-12。起点：`b8f74d51bd844a178918c331953a782ca539a08e`。本文件记录新一轮优化方案；完成情况以本轮验收报告和实际执行证据为准。

## 现状与技术取舍

现有分析已经具有检索增强生成（RAG）的基本链路：对当前授权、已发布且生效的目录、词典、规则和资料进行词法召回，模型只根据实际片段回答，服务器回填引用并独立复核。它不是向量检索；当前配置明确关闭嵌入模型，真实端点已验证的能力是 `deepseek-v4.1-flash` 对话、原生 JSON Schema、thinking 关闭。

主要缺口是未维护同义表达时的召回、固定字符分块切断条件和例外、语义处理过程不可见，以及历史失败后重新组织问题的操作成本。继续增加针对样例的词表不能解决这些共同问题。

本轮实现模型辅助的多查询 RAG：原问题参与确定性词法召回，真实模型补充检索表述，再在同一授权语料内融合和重排。它使用现有 `real,mcp`、`agent.semantic.mode=active` 的真实模型与认证 HTTP MCP 链路，不增加前端依赖或模型供应商。数据查询、金额计算与知识解释仍有独立的证据边界。

向量检索适合进一步提升零词项重合和大语料召回，但需要独立验证嵌入端点、维度、模型版本、出站隐私、向量距离、发布版本索引激活、撤权删除和召回评测。当前最多 100 份资料、1600 个片段的范围内，可先检验多查询 RAG 的实质收益；没有真实嵌入能力和评测证据前，不使用哈希向量冒充语义向量，不宣称完成向量数据库或外部文档系统接入。

## 实施范围

1. **段落与句子分块。** 按已脱敏原文的段落、句子边界生成有界片段，长句有确定性切分和少量上下文重叠；不拆 Unicode 代理对，不丢字符。标明片段、原文行号和字符位置；元数据与正文一起受 2000 字符引用上限保护。分块算法版本进入知识快照指纹。
2. **整轮批量语义检索。** 计划经原有独立复核后，收集至多六个知识子问题。一次真实模型调用通过两个明确的可空字段生成每题至多两个检索改写；不依赖端点对数组数量上限的遵守，不截断超额响应。原始用户问题和原知识子问题始终保留。检索文本不能修改权限、时间、生效资料、业务执行条件或用户意图，也不能成为回答事实。
3. **确定性融合与有界重排。** 每路在完整授权语料内评分，以片段 ID 去重计算匹配并集，用排名融合和来源均衡形成候选。整轮最多 24 个不同片段、48 KiB 候选上下文，按问题轮询分配。一次真实模型调用仅重排实际候选编号，程序校验完整排列、无重复、无缺失、无越界；支持、反驳和例外均为相关资料。最终每题最多 12 片，优先不同来源；超过来源、片段或字节预算时明确说明覆盖有限。
4. **可解释的语义试查。** 保留现有无需模型的词项试查；新增清楚标注模型调用的语义试查，与分析执行共用 RAG。展示实际改写、每条来源的召回路径、候选/重排数量和截断。排名不表示答案可信度。返回前重新核验权限和完整版本；失败不能静默退回旧结果或词法结果。
5. **资料导入与分析恢复。** 在资料编辑器中支持有大小和编码检查的本地 UTF-8 文本/Markdown 导入，仅回填草稿，来源及发布继续明确核对。终态任务可以回填原问题、公司、报表和显式快照，用户重新提交才创建新任务、新请求号；不自动重新推理。首次发送前以当前登录会话摘要绑定会话存储并回读核验，传输结果未知时保留完整原请求与请求号；同标签刷新或离页返回只恢复，不自动提交，不和终态重做混淆。核对失败、会话变化、24 小时期满和存储不可用分别说明。
6. **专项质量与失败证据。** 以独立标注的相关来源衡量检索 Recall@12、首个相关来源排名、反对依据保留和无命中行为，并分别记录真实模型调用、用量、延迟和最终有据回答。保留一次通过率、失败、修复和最终复验，不以状态机测试替代真实链路证据。
7. **模型响应与日志边界。** 真实复测出现 HTTP 400 及媒体类型异常后，补充仅含固定分类、计量与摘要的传输诊断。共同入口限制原始响应为 512 KiB、诊断前缀为 16 KiB，并在 SDK 前拒绝畸形成功响应和会触发原文日志的非法元数据；响应协议与预算进入配置摘要。不得用隐式重试、关闭独立复核或打印完整提示换取通过。

## 不可破坏的约束与预算

- 先授权、选发布版本并检查生效期，再召回。草稿、停用、过期、其他租户/公司/报表内容不得进入模型上下文。知识正文是数据，不能授予工具或角色权限。
- 原有计划/回答的独立复核保留；新增两个批量阶段至多增加两次模型调用，整轮上限由 8 次调整为 10 次、总时限由 180 秒调整为 240 秒。单次模型仍最多 40 秒，实际请求仍最多 128 KiB，回答依据仍最多 80 KiB。
- 模型、提示、Schema、检索算法、预算和分块版本进入执行配置摘要；Schema先规范对象键序，排队任务不能因同一契约的序列化顺序变化误失效，也不能静默切换实际版本。取消、失租、权限撤销和发布版本变化后不得发布迟到结果。
- 多路检索计数按实际 ID 并集，不能累加各路命中数或从返回片段数估算搜索覆盖。模型未执行、检索没有命中、候选截断是不同事实。
- 本轮不改变字段类型、约束、索引或业务数据库结构；同步分析阶段字段注释中的两个新阶段，验证空库注释覆盖并核对除注释外结构保持。固定演示库 `report_demo` 保留。
- 真实工单、外部 ERP、正式外部认证、生产容量与灾备仍在暂缓范围；本轮不宣称生产准入。Demo 账号生命周期及前端依赖版本遵守既有范围约定。

## 验收与数据操作

用户已授权本轮所需的实施、自测及清理，无需重复确认。复用 `analysis_knowledge_it_<UUID>` 等已明确归属本仓库的隔离夹具：执行前记录所有已有库及准确新库名，用于资料版本/权限、RAG、任务恢复、真实模型、认证 HTTP MCP 与浏览器验收；结束后只删除本轮创建的已核实目标，保留 `report_demo`、执行前已有库和无关数据。

验证顺序：分块/融合/重排契约及前端恢复单元测试 → 数据库与状态边界 → 真实模型语义改写、跨语言、否定/例外、相似概念区分、冲突与拒答 → 浏览器资料导入、两类试查、引用、失败恢复、刷新/迟到响应 → 受影响模块回归、前端构建与仓库检查。执行 `node tools/check-comments.cjs`、`node tools/check-docs-real-model.cjs`，按需要执行基线与无旧兼容检查。

证据先保存到本轮专用目录，归档时排除凭据。临时凭据和隔离库在验收后清理。Codex 内嵌浏览器标签保持打开，不为清理自动关闭或销毁，遵守全局已知崩溃规避规则。
