## 3. 业务规则和异常处理

| 场景 | 当前要求与后续验收口径 |
| --- | --- |
| 报表不存在、未发布、停用或无权限 | 不返回可执行预览；不向无权用户暴露内部目录信息 |
| 同名/别名冲突或候选接近 | V2 请求澄清，用户明确报表后重新查询 |
| 预览为空 | 返回明确 0 条结果，不继续使用上一份预览 |
| 新查询或新清单 | 旧卡片以服务端状态作废；迟到任务不能覆盖较新的查询 |
| 排除记录 | 必须属于来源预览；优先使用报表ID+记录ID区分重复单据号 |
| 查询被拒绝后省略公司 | 保留未生效的请求范围并再次拒绝/澄清，不能静默回退到成功公司的旧预览 |
| 名称漏提取或协议不合法 | 停止本轮业务动作；未解决范围不能用于后续省略条件的派单 |
| 仅调整记录选择 | 复用同一有效预览；语义排除项同步到复选框并保存，刷新后恢复 |
| 目录、规则或权限改变 | 旧预览/清单不能跳过校验执行 |
| 同时确认或重复请求 | 幂等返回或拒绝冲突，不重复派单 |
| 部分成功 | 保留逐条结果，只允许按规则重试明确失败项 |
| 外部超时或结果不明 | 标记待核对，先查询原请求；不得把无响应判为成功或全量重试 |
| 运营关闭 | 仅关闭已知失败，不伪造成功，也不能关闭仍在途或结果不明的条目 |
| SSE 中断/页面刷新 | 通过会话消息、卡片状态和预览任务查询恢复结果 |
| 会话删除或结果留存到期 | 分批清理；未决业务适用保留条件，清理后不允许迟到消息复活 |

## 4. 数据和指标口径

1. 业务状态以 MySQL 的预览、清单、条目和网关请求流水为准；新语义路径的请求/生效范围另存状态表，不从助手文字或 Redis 记忆推断权限和成功范围。
2. 预览条数和金额按被冻结的候选记录汇总；分页数量应与摘要一致，0 条报表保留明确说明。
3. 派单成功率依据当前清单条目状态统计，重试不重复累计同一条目的成功；未知结果应单列。
4. 指标按租户、操作、报表、版本和结果分组，平均耗时与 P95 使用实际记录样本。现有后台指标不是目标环境 SLO 承诺。
5. 留存默认会话/结果/审计 365 天、指标 90 天，最终以租户 `retention` 策略为准。去重请求标识和必要终态有保留规则，不等于删除所有业务痕迹。
6. 数据模型与升级以 Flyway 为准，勿按历史建议 DDL 手工创建一套不同表结构。只读核对 SQL 见 [技术选型附录 A](派单Agent技术选型.md#附录-a只读业务核对-sql)。

| PRIV-01 | 真实敏感格式跨 SSE 分片及日志/导出 | 不泄露敏感值；删除与保留符合批准口径 |

具体测试命令和隔离数据库开关以 README 为准。启用共用演示环境的 `DEMO_IT` 前应确认数据可丢弃；`TRACE_IT`/`P2_IT` 的 UUID 数据库隔离不代表可以共享生产 Redis。

## 6. 上线判定

上线前由业务确认数据/规则口径，测试给出当前候选版本的结果，运维确认恢复与升级方案。至少满足真实身份可信、跨租户权限有效、外部请求幂等与可核对、旧预览不可执行、部分失败可恢复、目标容量达标、留存和审计有明确责任人。

历史评审记录可作为问题样例和回归来源，但其测试数量、结论日期及原设计不替代本轮验收。项目下一阶段的产出应是上述真实接入和目标环境证据，而不是继续重复实现已经具备的目录、分页或持久状态功能。
