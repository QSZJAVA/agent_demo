# 当前真实模型语义与持久派单流程

> 历史归档：保留原日期、版本与验收范围。当前运行说明以仓库根目录 README 和 demo-baseline.json 为准。


2026-10-03，基于当前源码。八页依次为总流程、模型解析与校验、多轮范围规划、报表链接、预览/选择、确认/核对、SSE 恢复、持久派单任务恢复。源码生成器为上一级的 `build-semantic-flows.cjs`；同目录 HTML、SVG、Mermaid 和 draw.io 为同一份节点/连接定义生成。

场景为 `real,mcp`、`agent.semantic.mode=active`，语义来源为 MODEL。模型名、原生 Schema 和 thinking 选项由实际配置决定；默认 native-schema=false，不能依据此图宣称某个端点已验证原生 Schema 能力。本轮未重新调用真实模型。

自然语言只查询、调整范围、生成待确认清单或读取/取消状态。用户明确确认后，前端先保存稳定任务键，再向 `/api/dispatch/jobs` 提交结构化操作；后台重新校验当前身份、清单和版本，通过 HTTP MCP 业务服务逐项事务复核。原认领的 executionVersion 随网关请求冻结传递，禁止发送时借用新执行者的版本。

任务与清单状态分别保存。任务 QUEUED 最多等待 10 分钟，跨实例通过数据库锁认领 RUNNING，5 分钟运行租约每 30 秒续租。失效的 RUNNING 任务记 FAILED，不自动重发；业务清单仍按自身可靠状态决定是否等待、核对或允许显式失败重试。任务 SUCCEEDED 代表操作已完成，逐项派单成功率以结果中的实际成功/失败数为准。

断线或刷新后使用任务号读取结果；丢失提交响应时沿用提交前保存的幂等键。恢复执行卡片只读取既有任务，不创建新的写入。未知业务结果使用原请求号核对，不能把超时当作未派单。结果按运营 resultDays 保留策略清理，幂等身份继续保留。

本轮有数据库/状态机回归、组件方法测试、真实 Agent HTTP → HTTP MCP → 隔离业务表验收；未做浏览器 E2E、真实模型重评、正式 ERP 接入或完整容器部署。当前业务服务仍操作仓库业务表。Demo 账号和前端版本按仓库规则暂缓处理，企业正式认证系统尚未接入。

代码入口：`DispatchJobController`、`DispatchJobService`、`DispatchService`、`McpDispatchGateway`、`BusinessDispatch`、`frontend/src/api/dispatchJob.js`；数据库结构见 V20。完整修复记录见 [修复与验收](../../非账号问题修复与验收_2026-10-03.md)。
