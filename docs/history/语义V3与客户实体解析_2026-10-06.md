# 语义 V3 与客户实体解析（2026-10-06）

> 历史归档：保留原日期、版本与验收范围。当前运行说明以仓库根目录 README 和 demo-baseline.json 为准。


> 本文保留 V3 当时的设计与能力边界；当前字段筛选及运行基线以 [V4 配置字段设计](语义V4配置字段筛选_2026-10-06.md) 为准。

当前业务链路使用 `real,mcp`、`agent.semantic.mode=active`、真实模型接口及带身份认证的 HTTP MCP 业务服务。V3 将业务范围、记录操作和实体解析分开；客户名称、别名和测试问法不写入解析提示词。本文描述当前实现，测试结果另由本轮验收报告记录，不能引用旧版通过率证明 V3 已验收。

提示词包含固定规则与三个抽象语义对照：记录限定、明确查询并排除、排除后恢复。对照只使用“报表甲／客户甲／示例单据”作为结构占位符，随协议维护，不逐客户或逐问法扩展。`SemanticContractResourcesTest` 检查对照符合当前 Schema，并阻止两组评估客户名称和完整问法进入提示词；所有运行语义仍由真实模型解析。

## 解析与执行边界

1. `ModelIntentParser` 读取稳定规则资源、当前授权报表目录及别名、会话状态和 `SemanticCapabilities`，输出 V3 意图。上下文不包含全租户客户名单。
2. `IntentCodec` 验证分类型 Schema、字段组合、本轮原文证据、禁止动作及无法支持的条件。结构校验后还会在无副作用的计划草稿上检查范围矛盾；一次校验修正携带明确错误码；仍不可靠则澄清或失败，不自动生成替代意图。
3. `SemanticPlanner` 在草稿上归并范围，并核对每个报表实体的最终角色，全部通过后才提交。等价的范围操作可以归并，不要求每个提及的报表都对应一次修改。
4. `SelectionResolver` 仅在当前完整授权快照中定位单据、摘要或客户，再计算排除集合。报表限定只影响指定报表；本轮任何选择失败都不提交部分选择。
5. 预览及清单冻结客户实体、规则与版本。生成清单不代表执行；用户确认后业务服务仍复核租户、公司、报表、确认、幂等请求号、执行版本及客户归属。

## 当前协议

`intent-v3.schema.json` 使用分类型分支限制目标、操作、选择类型及数量字段的组合。模型不能为记录输出反向集合含义的 ADD/REMOVE。

| 内容 | 当前语义 |
| --- | --- |
| COMPANY | 数据归属公司，支持 REPLACE 一家或 CLEAR 全部授权公司，不表示客户 |
| REPORTS | REPLACE 替换、ADD 追加、REMOVE 移除、CLEAR 恢复全部授权报表 |
| RECORDS | EXCLUDE 排除、RESTORE 恢复指定记录、REPLACE_EXCLUSIONS 替换排除项、RESTORE_ALL 恢复全部 |
| selectorKind | DOCUMENT 单据号、DESCRIPTION 摘要、COUNTERPARTY 客户实体；不适用时 NONE |
| quantifier | ONE 唯一记录、ALL 全部匹配、UNSPECIFIED 数量未明确；多条匹配而没有集合含义时澄清 |
| reportMentions | 记录所属报表限定；COMPANY/REPORTS 操作必须为空 |
| reportConstraints | 仅补充操作未直接表达的约束：INCLUDED 在最终范围内、EXCLUDED 在范围外、RECORD_SCOPE 用于记录定位 |
| unsupportedConditions | 无法支持的条件原文；非空时只能澄清，不执行已识别的其他部分 |

CLARIFY 可保留已识别的候选操作作为审计证据，但状态机在归并前终止，不应用候选范围、不查询或建单。报表范围和记录选择同时出现时必须有独立的范围原文证据，不能将客户限定整句重复解释为范围替换。英文报表别名也不能命中含数字单据标识的一部分。

当前仍不支持自然语言日期、金额、排序、数量上限和多步查询程序。结构校验不能证明自然语言理解绝对正确，真实模型仍须通过独立评估；无法确定时要求澄清。

## 客户实体契约

业务报表通过已有受控字段配置声明 `counterpartyId`、`counterpartyName` 和可选 `counterpartyAliases`。前两项分别提供稳定客户标识和完整名称，别名为来源维护的 JSON 字符串数组，最多 32 项。标准适配器经参数化查询读取，HTTP MCP 的既有分页事实接口传递这些字段，不新增任意 SQL 接口。

本仓库应收示例表提供 `customer_id`、`customer_name`、`customer_aliases`。外部业务表仍由所属系统维护；接入时映射其真实标识，不能用名称哈希或行号伪造客户主键。新增客户属于业务数据维护；新增报表的客户能力通过字段配置声明，不修改解析提示词。

客户按当前租户、授权公司和限定报表内的完整名称或已维护别名进行精确规范化匹配。ALL 只展开已经唯一确定的客户，不能绕过同名客户或共享别名的歧义；不按名称相似度自动合并客户。未维护别名、客户信息缺失或单笔指代不唯一时，用户需给出明确单据或在表格中选择。

实体关联可以按模型已声明的类型去掉一次“客户／交易对方”或“发票／单据号”等称谓；原词和去称谓候选同时参与精确匹配。若两种形式分别命中不同客户或单据，必须澄清，不能优先取一个。该步骤不解析动作、不递归删词、不生成新别名，也不修改原始模型证据。

`dispatch_preview_item.counterparty_json` 与 `dispatch_plan_item.counterparty_json` 保存 `{id,name,aliases}`。空表示来源记录没有客户实体；损坏数据不能降级为摘要匹配。当前快照冻结名称和别名，刷新会话仍恢复同一选择；真正重新查询会获得新快照。执行时客户稳定标识变化会拒绝派单。全部匹配必须基于完整快照，不能把分页缺失当成少量匹配。

## 最新数据基线

本次修改 V5 基础快照结构、V21 当前注释清单、目录事实配置及 Demo 初始化脚本，旧库不做原地转换或 Flyway 校验和修复。只对新建或明确重建的本仓库专用库运行最新初始化；本轮日常旧库保持原数据，不承诺旧会话、预览或浏览器状态可恢复到 V3。


## 分层验证

- 协议与集合回归检查原子性、数量、权限、客户标识、别名冲突和名称替换性质；不计入真实模型准确率。
- 独立 MySQL 空库检查最新初始化、39 张表的注释及新增快照字段；持久化测试检查选择和客户快照恢复。
- HTTP MCP 回归检查真实服务传输、身份隔离、客户事实和执行前客户归属复核；测试库中的合成业务数据不代表外部 ERP 验收。
- 原业务语料为回归集，`generalization-holdout.json` 与 `generalization-reserve.json` 分别保存保留集 A、B 的客户名称和表达，均不进入提示词。它们不用于提示词样例检索。任何查看结果后针对性修改均须如实记录，不能继续把调优后的成绩称为首次盲测。
- `tools/test-semantic-generalization.ps1 -Repetitions 3 -Corpus generalization-reserve.json` 保存每轮成功、失败、调用次数、格式修复、错误就绪计数、提示词及语料哈希，不通过只重试失败题的方式拼出全量通过。

真实模型语义回放使用合成候选记录，不访问业务库或执行派单；浏览器、HTTP MCP、实际派单须分别取证。正式外部认证系统、外部 ERP、生产容量和灾备验收仍待各自实际接入与验证。
