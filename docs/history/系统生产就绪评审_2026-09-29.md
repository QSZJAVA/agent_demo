## 已确认缺陷

### R1 / P1：否定派单的表达被错误应用到报表范围

位置：`backend/src/main/java/com/example/report/semantic/DomainIntentParser.java:77`，以及第 101 行附近的 `negativeSend` 判断。

在新会话上下文中输入：

```text
只查销售报表，不要派单
查一下销售报表，不要派单
```

两条输入都被领域解析器接受为 `action=PREVIEW, reports.operation=REMOVE`。经过协议校验、范围合并、实体覆盖校验和权限校验后，实际报表范围是：

```text
[rpt-ar-invoice, rpt-expense-claim]
```

预期应查询销售报表，或对不确定句式澄清/交给模型；实际却排除了销售报表，查应收和费用报表。原因是整句任意位置出现 REMOVE 词就参与报表操作判断，没有把“不要”的作用对象绑定到“派单”。`negativeSend` 又要求没有报表实体，无法保护该句式。

影响：查询范围与用户要求相反，后续省略报表的建单可能继承错误范围。仍需点击确认才执行，未发现这里绕过确认直接派单。

建议：先识别动词否定的作用范围；不能证明唯一含义的复合语句应退出领域解析。新增包含不同语序、标点、否定对象以及后续“剩下的派单”的多轮验收。

复现文件：`docs/review/ProductionReadinessSemanticProbe.java`。它调用当前真实解析器、协议校验和 Planner，不调用模型、不执行派单。

### R2 / P1：恢复排除项失败后仍能按全选生成清单

位置：`frontend/src/components/agent/AgentChat.vue:447`，建单分支位于第 501 行附近。

复现场景：已有有效预览且此前排除一条记录；重新打开会话，历史消息请求成功，而 `/selection` 请求失败。

实际行为：打开会话先清空本地选择；`restoreSelection` 捕获异常后不保留恢复失败状态；`openingHistory` 被释放，建单按钮可用。点击后发出的请求为：

```json
{"conversationId":"conv1","previewId":"p1","excludedRecords":[]}
```

预期应维持“选择尚未恢复”的状态，要求重试恢复或明确重新选择。当前 `createPlan` REST 路径直接采用请求的排除列表，不会自动补入语义会话里已保存的排除项，因此存在扩大待确认清单的风险。最终确认仍保留。

建议：区分“已确认全选”和“选择未知”；恢复失败后禁止建单，提供恢复重试或明确重置选择入口。增加选择版本校验可进一步防止多标签覆盖。

复现文件：`docs/review/production-readiness-ui.probe.cjs`。它执行当前 Vue 组件真实方法，注入选择接口失败，验证最终建单参数；这是方法级复现，不是浏览器端到端验收。

### R3 / P1（条件性安全风险）：Vite 受影响版本配合对外开发监听

本次构建使用 Vite `5.4.21`；`frontend/vite.config.mjs` 中 `server.host=true`。当前工作环境是 Windows。

`npm audit --json` 报告 5 个受影响包条目：高危 1、中危 1、低危 3；这不是 5 个相互独立的漏洞。高危条目为 Vite，包含 Windows 路径下 `server.fs.deny` 绕过等公告。

维护者公告说明：向网络暴露开发服务器，且允许目录中存在相应敏感文件时，Windows/NTFS 路径变体可导致禁止访问的文件内容泄露。当前版本与监听设置满足部分风险条件；本次未读取敏感文件、未进行漏洞利用验证，因此不声称已经发生泄露。

来源：[Vite 维护者安全公告 GHSA-fx2h-pf6j-xcff](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff)。

建议：开发服务默认仅绑定回环地址；升级到与插件兼容且修复相关公告的版本并回归。不要直接执行可能降级依赖或跨大版本升级的 `npm audit fix --force`。Docker 前端运行 Nginx 静态产物，不运行 Vite 开发服务器，因此不能把这项风险直接等同于生产 Nginx 漏洞。

## 生产上线缺口（区别于新增 Bug）

1. **可信认证尚缺。** `PermissionService.java:36` 根据客户端提供的 `X-User-Id` 查询硬编码用户；能够访问服务并提供 `admin` 身份头的调用方可成为演示管理员。Basic Auth 只能限制进入演示站点，不能提供真实用户、组织和租户授权。该限制已在文档声明，仍是正式上线门槛。
2. **外部业务接入待验收。** 本报告当时未取得外部业务系统的接入证据。当前真实模型与独立 MCP 服务已实现，本仓库业务表的事务派单已有验证；外部 ERP 的幂等、超时未知结果查询、对账及重试契约仍需独立验收。
3. **普通报表页面仍全量读取。** `ReportService.java:33` 起三条查询均为 `selectList`，未使用分页或条数上限。Agent 预览分页不能替代这三个入口的服务端分页。记录增长时存在数据库、应用内存及浏览器负载风险；本次未压测，不能给出安全容量。
4. **正式部署基线待补。** Compose 默认使用数据库 root；前端模板仅监听 HTTP 80。需要正式环境 TLS、最小权限账号、密钥管理、备份恢复、迁移回滚和在途任务升级策略。外部基础设施可能提供其中部分能力，但本轮没有其验收证据。
5. **真实模型与业务语料验收不足。** 领域语法命中的回放不能代表模型准确率；本轮未调用付费真实模型，未复跑历史模型评估。应分开统计 DOMAIN/MODEL 来源，验证误扩大范围率、澄清率、延迟及多轮语义。
6. **容量和可靠性未验收。** 本次隔离数据库回归不等于百万级数据、持续负载、真实多实例、依赖故障和容灾演练。需先定义业务数据量/并发/P95/可接受错误率，再验收。
7. **接口和维护债务。** 通用异常当前仍返回 HTTP 200 配合业务码；现有前端能识别，但网关监控和外部调用方必须按业务码统计或统一调整 HTTP 语义。Vue 2/Element UI、容器镜像和后端依赖需建立持续升级与安全扫描计划。
