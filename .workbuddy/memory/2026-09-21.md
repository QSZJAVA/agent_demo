## 踩过的坑（重要）

**Windows 下用 PowerShell 转码文件极易破坏中文**：我对 `deploy.sh` 做 UTF-8 转换时
误用 `[System.Text.Encoding]::GetEncoding(936)`（GBK），把已是 UTF-8 的字节按 GBK 解码再写回，
导致中文全部乱码、引号被吞掉，bash 报 `syntax error near unexpected token 'fi'`。
**教训：文件工具写入的就是 UTF-8，不要在 Windows 上对含中文的脚本做任何编码转换。**
（另：本机 PowerShell 工具的输出在部分情况下不回显，需把结果重定向到文件再 Read。）

### 新增 tools/pre-commit-hook.sh 提交前密钥扫描
安装：`cp tools/pre-commit-hook.sh .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit`。
设计要点（踩坑后修正）：
- `sk-` 规则必须用 `sk-[A-Za-z0-9_-]{20,}`，因为真实 Key 形如 `sk-wb-552c...` 中间带连字符，
  `sk-[A-Za-z0-9]{20,}` 会漏掉。
- 密码规则要能处理 `${VAR:default}` 形式：`[^:]*:` 会在第一个冒号处截断导致漏报；
  正确做法是用 `(\$\{[A-Za-z_]+:([^}]*)\}|([^[:space:]#]+))` 分别捕获取默认值与裸值。
- 必须排除钩子自身（其内容是待匹配的正则字符串），否则永远自我触发。
- 钩子输出用纯 ASCII，避免终端编码不同导致乱码。

## 本机环境的重要限制（务必记住）

- 本会话的 bash 工具被破坏：`dirname` / `ls` / `cp` / `head` / `mkdir` / `rm` 均不可用，
  且 `cd` 到带盘符路径失败，导致 `git` 的 hook、`bash -c` 脚本执行返回码与输出都不可信
  （实测钩子逻辑正确却总返回 1）。**结论：本机不要依赖 shell 脚本的输出判断结果，
  改用 Python 通过 subprocess 调用 git，或直接用 Read/Write/Grep 工具。**
- PowerShell 工具的 stdout 经常不回显；用 `[Convert]::ToBase64String` 编码后写文件、
  再用 Python 解码读取，是绕过编码混乱最可靠的方式。
- `wsl.exe` 被安全策略拦截，凡是会拉起 wsl 的命令都会失败。
