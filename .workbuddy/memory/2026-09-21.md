## Docker 部署方案（Linux 服务器）

为项目补齐了容器化部署能力，共新增 8 个文件：

- `docker-compose.yml`：编排 MySQL 8 + Redis 7 + backend + frontend 四个服务，
  仅 frontend 对外暴露端口（`${HTTP_PORT:-80}:80`），backend 用 `expose` 只在内网，
  通过 `depends_on: condition: service_healthy` 保证 MySQL/Redis 就绪后才启动后端。
- `backend/Dockerfile`：多阶段构建（maven:3.9-eclipse-temurin-17 构建 → eclipse-temurin:17-jre-jammy 运行），
  先 COPY pom.xml 跑 `dependency:go-offline` 缓存依赖层，再 COPY src 打包；
  非 root 用户运行，装 curl 做 HEALTHCHECK 打 `/api/report/sales`。
- `frontend/Dockerfile`：node:20-alpine 构建 → nginx:1.27-alpine 托管 dist。
- `frontend/nginx.conf.template`：用 `${SERVER_NAME}` 占位符，容器启动时 `envsubst` 渲染，
  避免把服务器 IP 烧进镜像；`/api` 反代到 `http://backend:8080`，**SSE 关键配置**：
  `proxy_buffering off` + `proxy_read_timeout 300s` + `proxy_set_header Connection ""`。
- `deploy.sh`：一键脚本（up/down/restart/rebuild/update/logs/ps/destroy/start-mock/start-real），
  自动生成含随机密码的 `.env`、探测公网 IP 填 SERVER_NAME、等四个容器就绪后打印访问地址。
- `.env.example` / `.dockerignore` / `docs/Docker部署指南.md`

## 踩过的坑（重要）

**Windows 下用 PowerShell 转码文件极易破坏中文**：我对 `deploy.sh` 做 UTF-8 转换时
误用 `[System.Text.Encoding]::GetEncoding(936)`（GBK），把已是 UTF-8 的字节按 GBK 解码再写回，
导致中文全部乱码、引号被吞掉，bash 报 `syntax error near unexpected token 'fi'`。
**教训：文件工具写入的就是 UTF-8，不要在 Windows 上对含中文的脚本做任何编码转换。**
（另：本机 PowerShell 工具的输出在部分情况下不回显，需把结果重定向到文件再 Read。）
